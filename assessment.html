balpyo · Dogfooding Assessment

Production-grade PPT를 만들기에 적합한가?

실제로 examples/quarterly-review/ 덱을 작성해 balpyo build로 웹·PPTX를 뽑아보고 산출물을 검증한 보고서 · 2026-09-14

결론: 아직 아니다 — "엔진의 심장"은 진짜지만, production 덱의 필수 요소가 빠져 있다.

핵심 기술(브라우저로 계산한 좌표를 편집 가능한 네이티브 OOXML로 굽고, 테마 색을 schemeClr 참조로 보존)은 실제로 동작하며 이 부분은 인상적이다. 그러나 표·차트·아이콘·커넥터가 전부 미구현이고, 슬라이드 레이아웃 CSS가 전부 빈 스텁이며, 테마는 내장 minimal 하나뿐이다. 지금 상태는 잘 설계된 Iteration 10 진행 중 개발 스냅샷이지 실무 덱 제작 도구는 아니다.

1. 무엇을 했나 (방법)

PRD의 비전이 아니라 지금 코드가 실제로 하는 일을 보려고, 사용자 입장에서 직접 써봤다.

  • go build ./cmd/balpyo — 바이너리 정상 빌드 (Go 1.26). balpyo v0.0.0-…+dirty
  • 실무 시나리오인 "분기 비즈니스 리뷰" 6장 덱을 examples/quarterly-review/에 새로 작성 — 표지·아젠다·KPI 카드·표·강조·마무리.
  • balpyo build --target html,pptx 로 두 타깃 산출.
  • PPTX를 python-pptx로 열어 도형 종류·좌표(EMU)·색 참조를 검증하고, HTML을 헤드리스 브라우저로 렌더해 확인.

작성하면서 만난 마찰(아래 3절)이 그대로 피드백이다.

2. 실제로 동작하는 것 — 그리고 잘 만든 부분

✅ 진짜 편집 가능한 PPTX

이미지로 찍은 슬라이드가 아니다. <text>→p:sp 텍스트박스, <shape>→p:sp AUTO_SHAPE로 나오고, 슬라이드 마스터·레이아웃·테마 파트·발표자 노트까지 갖춘 정상 OPC 패키지다. PowerPoint에서 열어 편집 가능.

✅ 테마 색이 참조로 보존

내 6장 덱 슬라이드 XML에서 schemeClr 61회 vs srgbClr 4회. 토큰 색은 테마 참조로 남아 PowerPoint에서 테마 색만 바꿔도 덱 전체가 따라온다. 리터럴 hex(그라디언트 스톱)만 srgbClr로 남는다 — 설계 의도대로.

✅ 좌표는 브라우저가 계산

저자는 EMU를 만지지 않는다. <grid cols="3"> 한 줄이 카드 3장을 (0.67", 1.40") 3.75×2.08"로 정확히 배치했다. 웹·PPTX가 같은 좌표계를 공유.

✅ 좋은 진단 메시지

모르는 태그·빠진 type·잘못된 variant를 줄·열 번호와 대안 목록까지 붙여 알려준다. 알 수 없는 variant는 에러가 아니라 폴백+경고 — 테마 교체가 덱을 멈추지 않게 한 판단이 좋다.

PPTX 지오메트리 검증 (내 덱, python-pptx)

slide 3 (KPI):  AUTO_SHAPE (0.67,1.40) 3.75×2.08  '+38% 월간 활성 사용자'
                AUTO_SHAPE (4.79,1.40) 3.75×2.08  '1.2B 분기 매출(원)'
                AUTO_SHAPE (8.92,1.40) 3.75×2.08  '4.6 앱스토어 평점'

                 TEXT_BOX   (4.40,2.83) 4.71×0.49  '추천 채널이…'   ← 가운데 앵커

<stack>의 9지점 앵커(at="top-right" 등)와 그라디언트·발표자 노트가 PPTX에 정확히 반영됐다.

3. Production 덱을 만들며 부딪힌 마찰 (실측)

🚫 표(table)가 없다 — 실무 최대 장벽

비즈니스 덱에 표는 필수다. <table>은 어휘에 아예 없다:

slides/004_table.slide:4:4: error: 알 수 없는 태그 <table>
  (쓸 수 있는 태그: a, blockquote, br, code, col, em, grid, h1, h2, h3,
   image, li, note, ol, p, pre, row, shape, slide, spacer, span, stack,
   strong, text, ul)

어쩔 수 없이 <grid cols="3"> + <shape> 9개로 표를 손으로 그렸다. 셀 병합·테두리 공유·헤더 반복이 없어 실무 표에는 부족하다.

🚫 <shape> 안에 레이아웃 컨테이너를 못 넣는다

KPI 카드에 숫자+라벨을 <col>로 세로 정렬하려 했더니:

slides/003_kpis.slide:6:8: error: <shape>의 자식으로 <col>는 올 수 없다
  (쓸 수 있는 태그: text, h1, h2, h3, p, blockquote, pre)

도형 안에는 텍스트류만 가능. 카드 안에서 정교한 배치를 하려면 도형을 겹쳐 쌓는 우회가 필요하다. <shape>는 variant로 외관을 지정해도 type이 필수라 <shape variant="stat-card">만으로는 안 되고 type="rounded-rect"를 매번 붙여야 한다.

⚠️ 슬라이드 레이아웃이 사실상 동작하지 않는다

layout="title", layout="two-column", layout="stat", layout="end"를 다 써봤지만 출력이 달라지지 않았다. 표지의 제목이 세로 가운데로 오지 않고 여느 슬라이드처럼 좌상단부터 쌓인다. 원인: 테마의 layouts/*.css 11개가 전부 빈 스텁이다.

$ cat core/themes/minimal/layouts/title.css
/* title 레이아웃 배치 CSS — 실체는 10/06에서 채운다. */

즉 지금은 실질적으로 content(세로 스택)와 canvas(자유 배치) 두 가지만 의미가 있다.

⚠️ 테마가 하나뿐 · 색이 5개뿐

내장 minimal 하나로 고정(resolve.go에서 하드코딩). balpyo.json의 theme 필드는 아직 선택에 쓰이지 않는다. 색 토큰은 fg·bg·muted·surface·accent1 5개 — accent가 하나뿐이라 다색 브랜드 팔레트를 표현하기 어렵다.

🐞 에러 메시지가 두 번 찍힌다

빌드 실패 시 모든 진단이 정확히 두 번 출력된다. main.go가 result.Diagnostics를 찍고, 그 뒤 diags.Err()가 같은 진단을 합쳐 만든 error를 또 찍기 때문(pipeline.go). 사소하지만 눈에 띄는 UX 버그.

5. 지금 위치 (개발 단계)

TASKS.md 기준 Iteration 10(레이아웃 카탈로그 + 테마 패키지 포맷) 진행 중이다. Iteration 0–6, 8은 완료(7은 건너뜀), 7·9·11과 Phase 2(표/차트/아이콘, init/server 등)는 미착수. 테마 패키지 로딩(tokens/components)은 최근 커밋으로 들어왔고, 레이아웃 CSS 실체와 테마 선택이 아직 남았다. 순조롭게 잘 진행 중인 프로젝트지만, 로드맵상 production 필수 기능들이 아직 앞에 있다.

7. 권고

지금 적합한 쓰임

  • 텍스트·불릿·카드·도형 중심의 단순한 내부 덱
  • 테마 참조 PPTX가 필요한 기술 검증(PoC)
  • 엔진·테마 시스템 기여/개발

Production 전 필요한 것

  • 표·차트 구현 (최우선)
  • 레이아웃 CSS 채우기 (title/2단/stat…)
  • 다색·다중 테마 + theme 선택
  • 도형 안 레이아웃 컨테이너 허용
  • 중복 진단 출력 버그 수정

한 줄 요약: 기반 기술은 이미 production 급이지만, 그 위에 얹을 콘텐츠·레이아웃 어휘가 아직 production 급이 아니다. 방향과 설계는 탄탄하니, 표·차트·레이아웃이 채워지면 판단이 크게 달라질 것이다.
