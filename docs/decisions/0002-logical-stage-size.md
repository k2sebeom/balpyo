# 0002 — 4:3 논리 스테이지는 960×720이다

- 상태: 확정
- 날짜: 2026-08-17
- Iteration: 0
- 관련: PRD §6.2, §13-5, §13-9

## 맥락

PRD는 세 가지를 동시에 못 박고 있었다.

1. 수치는 **논리 스테이지 px 단일 단위**이고, PPTX 변환 계수는 **`1px = 9525 EMU`** 상수다 (§13-5).
2. PPTX 페이지 크기는 종횡비와 연동된다 — 16:9는 13.333×7.5in, **4:3은 10×7.5in** (§6.2).
3. 논리 스테이지는 16:9가 1280×720, **4:3이 1024×768** (§13-9).

세 조건은 함께 성립할 수 없다.

| 스테이지 | ×9525 EMU | 인치 |
|---|---|---|
| 1280×720 | 12192000×6858000 | 13.3333 × 7.5 ✅ PowerPoint 와이드 표준 |
| 1024×768 | 9753600×7315200 | 10.6667 × 8.0 ❌ 표준 4:3(10×7.5)이 아니다 |

1024px를 10in에 맞추려면 계수가 `8929.6875 EMU/px`가 되어야 하고, 그러면 종횡비마다
변환 계수가 갈린다. "저자와 지오메트리 패스가 같은 좌표계를 쓰므로 환산 분기가 없다"는
§13-5의 근거가 무너지고, 정수가 아닌 계수는 좌표마다 반올림 오차를 남긴다.

## 선택지

1. **4:3 스테이지를 960×720으로 바꾼다.** 세 조건이 모두 성립한다.
2. **4:3 페이지 크기를 10.667×8in로 둔다.** 계수는 지키지만 산출물이 비표준 페이지 크기가
   되어, 기존 4:3 덱과 섞으면 PowerPoint가 슬라이드 크기 변환을 묻는다.
3. **종횡비별 변환 계수를 쓴다.** 페이지 크기와 스테이지를 모두 지키지만 계수가 갈리고
   반올림 오차가 생긴다.

## 결정

**선택지 1 — 4:3 논리 스테이지는 960×720이다.**

## 근거

- 960×720은 정확히 4:3이고, `×9525`로 정확히 10×7.5in이 된다. 세 조건이 모두 성립한다.
- 1024×768은 PPTX와 아무 관계가 없는 옛 화면 해상도였다. 지켜야 할 계약이 아니다.
- **두 비율이 높이 720을 공유한다.** 폰트 크기·여백·수직 리듬이 비율을 넘어 그대로
  통하므로, 테마가 두 비율을 모두 지원할 때 폭만 다루면 된다 (§8, `theme lint`의 부담이
  줄어든다).
- 계수가 정수 하나로 유지되므로 좌표 변환에 반올림 오차가 없다.

## 결과

- `soml.Aspect4x3.Stage()`는 `{960, 720}`을 돌려준다.
- PRD §6.2와 §13-9의 `1024×768`을 `960×720`으로 갱신했다.
