# 0006 — 발표자 뷰는 <html> 속성 하나로 켜고, 측정은 문서 뷰에서 한다

- 상태: 확정
- 날짜: 2026-08-18 (결정은 뷰어 런타임 도입에서)
- Iteration: 1.5 (Iteration 1 완료 후, 웹 런타임의 P0 절반 — PRD §9.1)
- 관련: PRD §9.1, §9.3, [지오메트리 패스](../internals/geometry-pass.md), ADR 0004

## 맥락

Iteration 1까지 웹 산출물은 슬라이드를 세로로 쌓은 정적 문서였다 — 스크롤로 읽을 수는
있지만 발표할 수는 없다. 산출물 `index.html`이 **발표 가능한 웹앱**이어야 한다: 슬라이드
한 장이 화면에 맞춰 나오고, 하단 컨트롤 바·키보드·해시 딥링크로 넘기고, 발표자 노트를
패널로 연다.

문제는 같은 HTML이 지오메트리 패스의 입력이라는 것이다 (PRD §9.3). 측정은 두 가지를
전제한다: 슬라이드 rect가 논리 스테이지와 1:1이고(스케일 금지 — `geom.newGeometry`가
검증한다), 모든 슬라이드가 그려져 있다(스크린샷 하네스가 슬라이드별로 잘라 찍는다).
발표자 뷰는 정확히 그 둘을 깬다 — 슬라이드를 겹치고, 화면에 맞춰 스케일한다.

## 선택지

1. **발표자 뷰를 기본 CSS로 두고 측정이 스케일을 역산한다.** 측정값을 배율로 나누면
   좌표는 복원되지만, "브라우저가 준 값을 스케일하지 않는다"는 지오메트리 패스의 단위
   전제(PRD §13-5)가 깨지고, 부동소수 나눗셈이 모든 좌표에 끼어든다. 겹친 슬라이드의
   스크린샷 문제는 그대로 남는다.
2. **발표용 HTML을 별도 산출물로 낸다.** 측정용과 발표용이 다른 바이트가 된다 — "재는
   바이트와 사용자가 받는 바이트가 같다"는 파이프라인의 성질(`pipeline.measure`)이 깨지고,
   두 파일의 배치가 갈라져도 아무것도 알려주지 않는다.
3. **문서 하나에 뷰 두 개를 두고 <html> 속성 하나로 전환한다.** 기본(속성 없음)은 지금의
   세로 스택(문서 뷰)이고, 런타임 JS가 로드 즉시 `data-balpyo-view="presenter"`를 켠다.
   발표자 뷰 CSS는 전부 이 속성에 걸리므로, 지오메트리 패스는 페이지를 열 때 속성을
   지우는 것(`web.DocumentViewExpr`)으로 측정 배치를 되찾는다.

## 결정

**선택지 3 — 속성 게이트 뷰 전환.**

따라오는 규칙:

- 전환 표현식과 속성 이름은 `render/web`이 소유한다 (`ViewAttr`·`PresenterView`·
  `DocumentViewExpr`·`PresenterViewExpr`) — 식별자 계약(ADR 0004의 `ElementID`)과 같은
  이유로, 계약의 양쪽(런타임 JS와 `geom.Session.Open`)이 같은 문자열을 써야 한다.
- 되돌리는 자리는 `geom.Session.Open` **하나**다 — 지오메트리 패스와 스크린샷 하네스가
  모두 이 관문으로 페이지를 열므로, 측정하는 모든 경로가 같은 배치를 본다.
- 발표자 뷰가 숨기는 슬라이드는 `display: none`이 아니라 `visibility: hidden`이다 —
  레이아웃이 남아야 뷰 전환이 줄바꿈을 다시 계산하게 만들지 않는다. 화면 맞춤은
  `transform: scale`이라 레이아웃 크기(offsetWidth)는 논리 스테이지 그대로다.
- 런타임 JS는 덱 데이터를 보간하지 않는 **고정 문자열**이다 — 슬라이드·노트는 DOM에서
  읽는다. 저자 텍스트가 스크립트로 새는 경로가 없고, 골든의 JS가 덱마다 다르지 않다.

## 근거

- 측정의 두 전제(1:1 스케일, 모든 슬라이드 그려짐)가 **검증 가능한 상태로 유지**된다 —
  속성 제거를 잊으면 `newGeometry`의 크기 검증이 "페이지가 스케일된 상태다"로 멈춘다.
  조용히 틀린 좌표가 산출물로 가는 경로가 없다.
- 산출물이 파일 하나로 남는다 — 발표와 측정이 같은 바이트를 쓴다.
- `balpyo server`의 발표자 뷰(PRD §9.2)가 같은 속성 계약을 재사용한다 — 서버는 속성을
  켠 채 서빙하고, 핫 리로드 후에도 뷰 상태가 속성 하나로 복원된다.

## 결과

- JS가 꺼진 브라우저에서는 문서 뷰(세로 스택)로 열린다 — 발표는 안 되지만 내용은 전부
  읽힌다. 의도된 폴백이다.
- 런타임은 지금 Go 문자열 인라인 JS다. PRD §9.1의 vanilla TS + `go:embed` 계획은 런타임이
  더 커질 때(reveal·오버뷰) 옮긴다 — 계약(속성·클래스)은 그대로 간다.
- 뷰어 크롬의 클래스(`balpyo-viewer-*`)가 계약에 추가되었다 — 발표자 뷰를 조작하는
  테스트(internal/testkit의 `TestPresenterView`)가 같은 문자열을 쓴다.
