# 0014 — `style` 탈출구의 경계: 문법은 에러, allowlist 밖은 경고, 값은 보지 않는다

- 상태: 확정
- 날짜: 2026-08-20
- Iteration: 3 (항목 02 — NOTES.md 03/02가 근거 기록이다)
- 관련: PRD §7.9 (탈출구), §5.3 (두 개의 선언 채널),
  [레이아웃 태그](../reference/soml/layout.md)의 `style` 절,
  ADR 0003 (외관은 인라인 style로 낸다)

## 맥락

PRD §7.9는 배치 CSS 탈출구를 정한다: 레이아웃 속성이 못 덮는 배치는 `style`로 통과시킬 수
있고, 배치는 어차피 좌표로 구워지므로 PPTX 충실도를 해치지 않는다. `style`에 외관 속성을
쓰면 웹 전용이 되고 dev 모드가 경고한다.

구현이 정해야 할 것은 **엔진이 이 문자열을 얼마나 보는가**다. 아무것도 보지 않으면 경고를
낼 수 없고, 전부 보면 CSS 엔진을 재구현하게 된다.

## 선택지

1. **전혀 보지 않는다.** 문자열을 그대로 인라인 style에 이어 붙인다. 경고가 불가능하고
   깨진 문법이 산출물의 마크업을 흔든다.
2. **프로퍼티 이름만 본다.** 선언을 쪼개 정규화하고 이름을 배치 allowlist와 대조한다. 값은
   보지 않는다.
3. **값까지 검증한다.** 프로퍼티별 값 문법을 알고 틀린 값을 에러로 낸다.

그리고 2번을 고른 뒤의 두 번째 질문: allowlist 밖의 프로퍼티는 에러인가 경고인가.

## 결정

**선택지 2 + 경고.** (`core/style.go`)

- 선언을 `;`로 나누고 첫 `:`로 쪼갠다. 프로퍼티 이름은 소문자로 정규화하고 값은 트림만
  한다. 결과는 `프로퍼티: 값`을 `; `로 이은 문자열이다.
- **값은 검증하지 않는다.**
- 이름이 배치 allowlist 밖이면 **경고**, 빌드는 계속된다 (`--strict`가 에러로 승격).
- 문법 위반(콜론 없음 · 이름 없음 · 값 없음)은 **에러**이고, 하나라도 있으면 `style`
  **전체**가 확정 배치에 실리지 않는다.
- allowlist의 기준: **지오메트리 패스가 재는 박스를 움직이는 프로퍼티**. `*` 접두 가족으로
  적어 CSS 명세를 베끼지 않는다.

## 근거

- **탈출구의 계약은 "우리가 보지 않는다"이지 "안전하다"가 아니다.** 선택지 3은 값 문법을
  아는 만큼만 통과시키므로, 엔진이 모르는 배치를 저자가 통과시킨다는 탈출구의 존재 이유를
  없앤다. 검증하는 값의 집합이 곧 새로운 속성 어휘이고, 그러면 그것은 탈출구가 아니다.
- **allowlist 밖을 에러로 두지 않는 이유는 같은 모순이다.** 에러로 만들려면 엔진이 CSS
  프로퍼티 **전체 목록**을 알아야 하고(모르는 이름을 거부해야 하므로), 새 CSS 프로퍼티가
  생길 때마다 엔진을 고쳐야 저자가 쓸 수 있다. 경고는 저자에게 사실을 말하면서
  (이 선언은 PPTX에 이식되지 않는다) 길을 막지 않는다 — 모르는 `variant` 경고와 같은
  경로이고, 엄격함이 필요한 CI는 `--strict`로 승격한다 (PRD §13-6).
- **문법 위반을 에러로 두는 이유는 값 문법과 다른 층이기 때문이다.** `width 100px`은
  "우리가 보지 않는 값"이 아니라 선언이 아니다. 빈 값(`width:`)도 CSS가 버리는 미완성
  선언이다. 여기서 침묵하면 저자가 쓴 배치가 조용히 사라진다.
- **부분 통과를 허용하지 않는 이유**는 예측 가능성이다. 세 선언 중 하나가 깨졌을 때 둘만
  적용되면 저자가 고친 뒤의 결과를 예측할 수 없다 — 값 층의 다른 속성과 같은 정책이다
  (틀린 값은 확정 값에 실리지 않는다).
- **allowlist 기준의 시험**: `translate`는 목록에 있고 `rotate`/`scale`은 없다.
  `getBoundingClientRect`는 이동한 박스를 재므로 좌표가 양 타깃에 도달하지만, 회전·확대는
  축에 정렬된 외접 사각형만 남겨 PPTX에서 다른 도형이 된다. `position`/`inset`/`top…left`도
  넣었다 — 좌표는 재어지므로 이식된다 (Iteration 6의 `x`/`y`가 열리기 전 저자의 탈출구).

## 결과

- 값을 검증하지 않으므로 인용 부호가 들어올 수 있다 — 웹 렌더러가 인라인 style 값을 HTML
  이스케이프한다 (그렇지 않으면 속성이 끊겨 마크업이 깨진다).
- 탈출구 선언은 인라인 style의 **맨 끝**이다 — 같은 프로퍼티면 뒤가 이기므로 저자가 엔진
  선언을 덮는다.
- 경고 경로의 회귀 감시는 골든 `diagnostics.txt` 하나다 (`03_layout/007_style_appearance`)
  — 문구나 조건이 조용히 바뀌면 그 골든 diff가 잡는다.
- 웹 전용이 된 외관은 픽셀 비교에서 갈라진다. 그 슬라이드에만 오차 조정을 주고 나머지
  슬라이드의 실제 배치 갈라짐이 그 그늘에 숨지 않게 한다 — 조정의 범위는 근거의 범위와
  같아야 한다.
