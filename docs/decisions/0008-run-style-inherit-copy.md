# 0008 — 인라인 런 스타일은 확정 스타일의 상속-복사로 확정한다

- 상태: 확정
- 날짜: 2026-08-19
- Iteration: 2 (항목 04 — NOTES.md 02/04가 근거 기록이다)
- 관련: PRD §7.7·§9.4, [텍스트 서브셋](../reference/soml/text-subset.md),
  [외관 속성](../reference/appearance.md)의 인라인 서식 표

## 맥락

인라인 태그(strong/em/code/a/span)는 자기 박스를 갖지 않는다 — 감싼 블록의 텍스트 흐름
안에서 런 서식이 된다. 렌더러 두 개(웹·PPTX)가 각자 런을 분할하므로, "런의 스타일이
무엇인가"를 어느 층이 어떤 규칙으로 정하는지에 따라 두 산출물이 갈라질 수 있는 지점이다.

## 선택지

1. **렌더러가 상속을 계산한다** — 잎에서 조상을 거슬러 올라가며 태그별 델타를 누적한다.
   상속 규칙이 렌더러마다 한 벌씩 생기고, 두 벌이 어긋난 순간 웹과 PPTX의 런 서식이
   조용히 갈라진다 — 그 종류의 버그는 두 산출물을 나란히 볼 때까지 드러나지 않는다.
2. **core가 요소마다 완성된 TextStyle을 확정한다 (상속-복사)** — `core.resolveInlines`가
   부모의 **확정** TextStyle을 복사해 태그별 델타를 얹고, 그 결과를 인라인 요소의
   Appearance에 싣는다. 렌더러의 런 분할은 "잎을 감싼 가장 안쪽 요소의 스타일 읽기"로
   끝난다.
3. **CSS식 지연 상속** — 확정 값 대신 "정하지 않음"을 남기고 렌더 시점에 채운다. 채우는
   규칙이 곧 상속 계산이라 1번과 같은 문제로 귀결되고, "렌더러가 보기 전에 모든 외관이
   확정된다"는 core의 계약(ADR 0003의 전제)을 깬다.

## 결정

**상속-복사(2번).** 캐스케이드(인라인 > variant > 컴포넌트 기본값 > 역할)는 블록에서
끝나고, 인라인은 그 **결과**의 복사 + 델타다 — variant와 역할이 인라인에 다시 적용되지
않는다. 델타: strong = 굵기 max(부모, 700), em = 이탤릭, code = mono 폰트,
a = 밑줄 + 링크 색 + Link, span = 자기 color/weight. `<br>`만 Appearance가 없다 (void —
서식이 아니라 흐름의 분절점).

## 근거

- 상속 규칙이 core 한 곳에만 있어야 두 렌더러의 런 서식이 같은 값에서 나온다. 렌더러는
  요소의 Attrs를 다시 읽지 않는다 — Iteration 1의 확정-외관 계약(ADR 0003)의 연장이다.
- **size의 상속 차단이 이 규칙의 핵심 사례다**: `<span size>`는 파서가 막고(allowlist),
  인라인 `<code>`는 code 역할의 크기(20px)를 끌어오지 않고 부모 크기를 따른다. 런 하나가
  커지면 웹의 줄 박스 높이가 변하는데 PPTX 줄간격은 문단 절대값(spcPts — ADR 0005)이라
  두 타깃의 글줄이 갈라진다 — 상속-복사가 아니었다면 이 차단을 렌더러 두 곳에 두 번
  구현해야 했다.
- 중첩 `<em>`은 토글하지 않는다 — 토글은 "몇 겹인가"를 세어야 뜻이 정해지는 규칙이라
  컴포넌트 조합(Iteration 11)에서 결과를 예측할 수 없게 된다. 복사 + 멱등 델타는 겹쳐도
  같은 결과다.
- strong의 max(부모, 700): OOXML 굵기는 켬/끔(`rPr@b`)뿐이라 더 굵은 단계가 없다 —
  h1(700) 안의 strong은 h1 스타일 그대로다 (깊은 비교 테스트가 고정).

## 결과

- 렌더러의 런 분할(웹 `runStyleCSS` 8선언 완전 명시, PPTX `rPr@b/@i/@u` 명시)은 잎에서
  읽기만 한다 — 웹과 PPTX의 순회가 같은 문서 순서, 같은 스타일 출처를 쓴다.
- `Appearance.Link`(href 원문)는 TextStyle 밖이다 — 스타일이 아니라 행동이다. 중첩
  인라인의 잎까지는 렌더러 순회가 나른다.
- `<span weight>`의 어휘도 같은 근거로 normal(400)·bold(700) 둘로 닫혔다 — CSS 9단계
  수치 축을 열면 중간 굵기가 웹에서만 동작한다.
- 블록이 Italic/Underline을 가질 수 있게 되는 날(variant가 필드를 얻는 날) 웹
  textStyleCSS와 PPTX 블록 런의 i/u 명시가 함께 넓어져야 한다 — 두 렌더러의 주석에
  이월로 남아 있다.
