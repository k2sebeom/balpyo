# 0004 — 지오메트리는 덱 모델이 아니라 곁 표로 두고 생성자로 주입한다

- 상태: 확정
- 날짜: 2026-08-18 (결정은 Iteration 1의 지오메트리 패스 구현에서)
- Iteration: 1
- 관련: PRD §9.3, §12.2, [지오메트리 패스](../internals/geometry-pass.md)

## 맥락

지오메트리 패스가 잰 요소별 좌표를 PPTX 렌더러에 전달해야 한다. 가장 손쉬운 자리는 덱
모델이다 — 요소마다 `Rect` 필드를 두면 렌더러가 요소만 보고 좌표를 얻는다.

## 선택지

1. **덱 모델에 싣는다.** `soml.Element`에 측정 필드를 추가하고 지오메트리 패스가 채운다.
   전달이 암묵적이라 편하지만:
   - 덱 모델은 **공개 계약**이다 (제3자 도구가 임포트한다). 브라우저 측정값은 저작 내용이
     아니라 파생 데이터인데, 공개 타입에 실리면 "언제 채워지는가"가 계약의 일부가 된다.
   - 값이 채워지는 시점이 **타깃 순서에 의존한다** — `--target html,pptx`와 `pptx,html`이
     웹 렌더러가 보는 덱을 다르게 만든다. 렌더러는 순수 함수(같은 덱 → 같은 바이트)라는
     성질이 깨진다.
2. **곁 표(side table)로 분리하고 생성자로 주입한다.** `geom.Geometry`가
   식별자 → 좌표 표를 들고, `pptx.NewWithGeometry(g)`로 좌표를 쓰는 렌더러에만 명시적으로
   넘긴다. 덱은 불변으로 남는다.

## 결정

**선택지 2 — 곁 표 + 생성자 주입.**

따라오는 규칙:

- 표의 열쇠는 `web.ElementID`가 덱 모델의 구조적 위치에서 만드는 식별자다 — 렌더 결과를
  파싱하지 않고 양쪽이 같은 문자열을 만들 수 있다.
- 표는 생성 시점(`newGeometry`)에 덱과 자리 하나씩 대조를 끝내고, 소비 측은 `Verify`로
  한 번 더 대조한다. 좌표가 엉뚱한 요소에 붙은 산출물은 열어 보기 전까지 정상으로 보이므로
  이 실패는 두 번 검사한다.
- 파이프라인 결과(`pipeline.Result.Geometry`)에도 남긴다 — 리뷰와 좌표 스냅샷 테스트가
  "이 빌드가 실제로 무엇을 쟀는지"를 다시 재지 않고 안다.

## 근거

- **의존이 타입에 드러난다.** `NewWithGeometry`의 시그니처가 "이 렌더러는 측정값이
  필요하다"를 말한다. 덱 필드는 그 의존을 숨기고, 좌표 없이 렌더된 덱이 조용히 원점
  도형을 낸다 — 지금은 렌더러가 시작 시점에 `Verify`로 멈춘다.
- **렌더 순서가 자유롭다.** 웹 렌더러는 측정 전의 덱과 측정 후의 덱을 구별할 수 없다 —
  덱이 안 바뀌기 때문이다. 타깃 순서를 바꿔도 산출물 바이트가 같다는 성질을 파이프라인
  테스트가 그대로 단정할 수 있다.
- **공개 API가 작게 유지된다.** 측정값의 모양(줄 박스 등)은 구현 사정으로 자주 바뀐다 —
  `render/geom` 안에 있으면 덱 모델 사용자에게 영향이 없다.

## 결과

- `render/geom/geom.go`(Geometry·Verify·newGeometry), `render/pptx/pptx.go`
  (NewWithGeometry·checkGeometry), `internal/pipeline/pipeline.go`(Renderers)가 구현이다.
- 좌표가 필요한 새 렌더러(PDF 등)는 같은 생성자 패턴으로 표를 받는다.
