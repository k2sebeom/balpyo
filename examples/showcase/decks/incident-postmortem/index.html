근본 원인 — 만료가 한 시각에 몰렸다

// 배포 때 캐시를 한 번에 채운다 — TTL이 전부 같은 시각이 된다.
func warm(ctx context.Context, ids []string) error {
  for _, id := range ids {
    if err := cache.Set(ctx, key(id), load(id), 30*time.Minute); err != nil {
      return err
    }
  }
  return nil
}
payments/cache/warm.go — 배포 훅이 부른다
① 일괄 예열
배포가 12만 키를 몇 초 안에 채운다.
② 고정 TTL 30분
지터가 없어 만료 시각이 하나로 모인다.
③ 같은 초에 전부 미스
단일 비행이 없어 미스 하나가 DB 질의 하나가 된다.
고정 TTL + 일괄 예열 = 스탬피드. 지터와 단일 비행(single-flight) 둘 다 없었다.

기여 요인 넷

고정 TTL
예열이 모든 키에 같은 만료 시각을 준다.
→ TTL에 ±10% 지터
단일 비행 없음
캐시 미스가 그대로 DB 질의가 된다 (cache.Get 실패 경로에 잠금이 없다).
→ 캐시 미스에 단일 비행 잠금
읽기 풀이 작다
풀 상한 40, 평시 피크 26. 여유가 14개뿐이었다.
→ 풀 상한 96, 사용률 80%에 경보
경보가 5분 평균
임계값이 평균이라 급한 스파이크를 늦게 본다.
→ 1분 p99 경보로 교체
넷 중 하나만 없었어도 47분이 아니라 5분이었다.
순서는 고치는 비용 순이다. 1번과 4번이 이번 주, 2번이 다음 스프린트.
재발 방지 액션
이번 주
1. TTL에 ±10% 지터 (결제 캐시 전부)
고정 TTL을 막는다
2. 5xx 경보를 1분 p99로 교체
탐지 12분 → 목표 3분
