What happened

120k payment cache keys expired in one second and hit the DB. The read pool ran dry; the API returned 5xx.

How it stopped

Load shedding, not a rollback. Once the cache refilled, errors were normal by 14:49.

Root cause

Every expiry landed at the same moment

payments/cache/warm.go — called by the deploy hook
// Fill the cache in one pass on deploy — every TTL ends up at the same instant.
func warm(ctx context.Context, ids []string) error {
  for _, id := range ids {
    if err := cache.Set(ctx, key(id), load(id), 30*time.Minute); err != nil {
      return err
    }
  }
  return nil
}
① Bulk warm-up
120k keys filled in seconds
② Fixed 30-min TTL
No jitter, so expiries converge
③ All miss at once
Each miss becomes a DB query

Contributing factors

Four things went wrong at once

Fixed TTL
Warm-up gives every key the same expiry
→ ±10% TTL jitter
No single-flight
Every cache miss goes straight to the DB
→ Single-flight on miss
Small read pool
Cap 40, normal peak 26 — only 14 spare
→ Cap 96, alert at 80%
5-min average alert
Averaging sees sharp spikes late
→ 1-min p99 alert

payments 5xx
Without any one of the four, this would have been 5 minutes, not 47.
