좌표는 브라우저가 잰다.
여기가 제품의 출발점이다. 저자가 계산할 것이 남아 있으면 자동화가 아니다.

한 소스, 두 산출물

1 · SOML 파싱
2 · 외관·배치 해석
3 · 지오메트리 측정
4 · 두 타깃 렌더
웹 · index.html 한 장
  • CSS와 발표 런타임이 인라인 — 파일 하나로 배포한다
  • 발표자 화면 · 개요 그리드 · 노트 · 장 링크
  • 브라우저 인쇄가 곧 PDF다
PPTX · 편집 가능한 원본
  • 텍스트 박스는 p:sp, 도형은 prstGeom, 표는 a:tbl
  • 슬롯은 p:ph 플레이스홀더 — 레이아웃이 살아 있다
  • 테마 색은 schemeClr — 이미지로 찍지 않는다
같은 SOML 트리가 두 번 렌더된다. 갈라지는 지점은 마지막 단계 하나뿐이다.
파싱은 soml, 해석은 core, 측정은 render/geom, 렌더는 render/web과 render/pptx다.

좌표는 브라우저가 계산한다

선언

저자는 flex와 grid로 배치를 선언한다. 좌표를 쓰는 자리가 어휘에 없다.

<row> · <col> · <grid> · <stack>
측정

헤드리스 Chromium이 요소마다 박스를 재고, 패스는 그 지오메트리만 읽는다.

getBoundingClientRect
굽기

잰 rect가 곧 PPTX 좌표다 — 1px은 9525 EMU이고 환산은 한 곳에만 있다.

a:off · a:ext
파이프라인이 주고받는 수치는 전부 논리 스테이지 px다 (16:9는 1280×720). EMU와 pt는 PPTX 렌더러 안에서만 존재한다.
이것이 두 번째 통찰이다 — 브라우저를 레이아웃 엔진으로 빌려 쓴다.

태그가 무엇이 되는가

SOML PPTX 산출
<text> · <h1> · <p> · <blockquote> p:sp 텍스트 박스 — 확정된 rPr을 싣는다
<shape> (프리셋 12종) p:sp + prstGeom — 자식 텍스트를 흡수한다
<image> p:pic + ppt/media 파트 (바이트 그대로)
<ul> · <ol> 도형 하나 — 불릿 문단이 한 박스에 산다
<row> · <col> · <grid> · <stack> 도형 0개 — 자식의 절대 좌표에 녹는다
<table> (이 슬라이드) p:graphicFrame + a:tbl — 편집 가능한 표
<chart> · <point> 도형 + 텍스트로 풀린다 — 막대 하나가 도형 하나
PowerPoint에서 글자를 고칠 수 있고, 표는 셀을 클릭해 행을 더할 수 있다. "열리는 파일"과 "편집 가능한 파일"의 차이가 여기서 갈린다.

토큰과 컴포넌트가 파일이다
  • tokens.json — 색 · 폰트 · 공간 · 반경 · 그림자
  • components.json — 역할 5종과 variant (kicker · card · stat-card · badge)
  • layouts 아래 CSS — 배치만 쓸 수 있고 외관을 쓰면 경고다
토큰은 눕지 않는다

토큰으로 쓴 색은 웹에서 CSS 변수로, PPTX에서 a:schemeClr로 남는다. 리터럴만 srgbClr가 된다.

→ PowerPoint에서 테마 색을 바꾸면 덱이 따라온다
토큰이 리터럴로 눕는 순간 제품의 약속이 깨진다. 골든 테스트가 그것을 감시한다.

두 렌더가 같은 컴포넌트를 낸다

무엇이 같은가
  • 요소 하나는 두 타깃에서 같은 종류의 객체다
  • 자리는 브라우저가 잰 rect, 외관은 해석된 값이다
  • 문서 순서가 곧 도형 순서다
줄이 어디서 접히는지는 각 엔진의 몫이다 — 약속 밖이다.
무엇이 판정하는가
  • PPTX에서 읽은 트리가 웹이 잰 트리와 같다
  • 모든 XML 파트가 ECMA-376 스키마를 통과한다
  • 같은 입력은 같은 바이트를 낸다
셋 다 go test ./... 한 줄에 들어 있다.
골든은 좌표 없는 레이아웃 트리와 진단 둘뿐이다 — 좌표는 동일성 판정이 매번 다시 재므로, diff에는 "도형이 하나 늘었다"만 남는다.
“열리는 파일”과 “편집 가능한 파일”의 차이가 이 제품의 핵심이다.
— 테스트 문서, 사람이 직접 pptx를 열어 확인하는 단계를 자동화하지 않는 이유
그래서 바뀔 때마다 PowerPoint나 Keynote로 직접 연다.
