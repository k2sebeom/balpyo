# 0037 — 문자 참조는 `;`를 요구하는 닫힌 어휘이고, 마크업이 아닌 `<`·`&`는 리터럴이다

- 상태: 확정
- 날짜: 2026-09-20
- 마일스톤: P0.1 (문자 참조와 리터럴 `<` — TASKS.md)
- 관련: PRD §7.7(텍스트 서브셋), ADR 0001(파서는 트리비아를 보존한다 — 무손실 렉서),
  [text-subset.md](../../docs/reference/soml/text-subset.md)

## 맥락

`examples/balpyo-intro`(도그푸딩 덱, D1)는 SOML 문법을 설명하는 덱인데 **자기 문법을 화면에
띄울 수 없었다**. 두 가지가 동시에 막혀 있다.

1. 텍스트 안의 리터럴 `<`는 언제나 태그 시작이다 — `a < b`는 "`<` 뒤에 태그 이름이 없다"
   에러가 된다.
2. 문자 참조를 해석하지 않는다 — 우회로 쓴 `&lt;`가 웹에서 `&amp;lt;`로 재이스케이프되어
   화면에 `&lt;`가 그대로 보인다.

그래서 코드·XML 예제·비교 연산자·수식이 전부 막힌다. 마크업 언어를 설명하는 제품이 자기
문법을 슬라이드에 못 쓰는 것은 기능 부족이 아니라 제품 모순이다.

## 선택지

**무엇으로 `<`를 쓰게 할지**:

1. **표준 문자 참조 5종 + 수치 참조** (`&lt; &gt; &amp; &quot; &apos;`, `&#60;`, `&#x3C;`).
   XML·HTML 저자가 이미 아는 표기이고 모든 콘텐츠 모델에서 한 규칙으로 통한다. 대신 XML
   예제 열 줄을 쓰려면 `<`마다 `&lt;`를 적어야 한다.
2. **`<pre>`·`<code>`에 CDATA 섹션 허용** (`<![CDATA[ … ]]>`). 원문을 **그대로** 붙일 수
   있어 코드 블록에 강하다. 대신 한 글자를 쓰는 데는 과하고, 인용 부호·`&`는 못 다룬다.
3. **둘 다.**

**마크업이 아닌 `<`의 렉서 규칙**:

1. **언제나 태그 시작** (지금). `a < b`는 에러다.
2. **뒤따르는 글자로 판정한다** (HTML5의 규칙): `<` + ASCII 글자, `</`, `<!--`,
   `<![CDATA[`만 마크업이고 나머지는 리터럴 `<`다. `a < b`가 그냥 쓰인다.
3. **공백이 뒤따를 때만 리터럴.** `a <b`는 여전히 태그로 읽힌다 — 규칙이 2보다 좁지만
   "글자면 태그"라는 한 문장으로 말할 수 없다.

**해석되지 않는 `&`의 처리**:

1. **XML 엄격**: 모든 `&`는 참조의 시작이다. `R&D`는 에러이고 `R&amp;D`로 써야 한다.
2. **`;`를 요구한다**: `&이름;`·`&#숫자;` 모양일 때만 참조로 **시도**하고, 그 모양이면서
   어휘 밖이면 에러(`&nbsp;`), 모양이 아니면 리터럴 `&`(`R&D`, `?a=1&b=2`)다.

## 결정

**선택지 3(둘 다) + `<`는 뒤따르는 글자로 판정 + `&`는 `;`를 요구한다.**

- **문자 참조는 닫힌 어휘 5종 + 수치 참조**다: `&amp; &lt; &gt; &quot; &apos;`,
  `&#1234;`(10진), `&#x27E8;`(16진). 그 밖의 이름(`&nbsp;`)은 **에러 진단**이다 — 어휘를
  닫는 제품이 참조만 열어 둘 이유가 없고, 지원하지 않는 이름을 조용히 리터럴로 흘리면
  화면에 `&nbsp;`가 보이는 것으로만 드러난다.
- **참조의 시도 여부는 `;`가 정한다**: `&[A-Za-z][A-Za-z0-9]*;`·`&#[0-9]+;`·
  `&#x[0-9A-Fa-f]+;` 모양만 참조로 읽는다. 그 모양이 아니면 **리터럴 `&`**다 — `R&D 예산`,
  `?a=1&b=2`가 저자가 쓴 대로 나간다.
- **`<`는 뒤따르는 글자가 정한다**: `<` + ASCII 글자 → 여는 태그, `</` → 닫는 태그,
  `<!--` → 주석, `<![CDATA[` → CDATA, **그 밖은 리터럴 `<`**다. `a < b`, `x <= y`,
  `1<2`가 그냥 쓰인다.
- **CDATA는 문자 데이터가 허용되는 모든 자리**에서 쓸 수 있다 (`<pre>`·`<code>`만이 아니다).
  내용은 **원문 그대로**이고 그 안에서는 문자 참조를 풀지 않는다. 공백 접기는 **부모의
  콘텐츠 모델을 따른다** — `<pre>` 안에서는 보존되고 `<p>` 안에서는 접힌다.
- **순서는 접기 → 풀기**다. 원문 공백 런을 한 칸으로 접은 **뒤에** 참조를 푼다. 그래서
  `&#32;&#32;`는 두 칸으로 남는다 — 저자가 참조로 명시한 문자는 U+00A0과 같은 급의
  "의도한 문자"이고, 접기의 대상은 원문에 있는 공백이다 (soml.Parse의 접기 계약).
- **속성 값도 같은 규칙으로 푼다.** `alt="a &lt; b"`가 동작하고 `href="?a=1&b=2"`는 그대로다.
- **산출물 경계에서 한 번 이스케이프한다**: 모델에 담기는 값은 **해석된 텍스트**이고,
  웹은 `html.EscapeString`, PPTX는 `escapeXML`이 그것을 다시 이스케이프한다. `&lt;`(원문)
  → `<`(모델) → `&lt;`(HTML·`a:t`)로 왕복이 닫힌다.

## 근거

- **둘 다 여는 이유**는 두 표기가 겨누는 크기가 다르다는 것이다. 문장 안의 한 글자
  (`Q1 &gt; Q2`)에 CDATA는 과하고, 열 줄짜리 XML 예제에 `&lt;`를 스물네 번 적는 것은
  저자가 포기하는 지점이다. 이 항목의 완료 증거가 "덱이 자기 문법을 보여준다"이므로 후자가
  실제 요구다. 구현 비용도 갈리지 않는다 — CDATA는 렉서 토큰 하나와 파서 분기 하나다.
- **`<`를 글자로 판정하는 이유**는 오탈자를 잃지 않으면서 리터럴을 얻기 때문이다. 리터럴로
  읽히는 `<`는 뒤에 글자가 없는 `<`뿐이고, 그것이 태그일 가능성은 없다 (태그 이름은 항상
  글자로 시작한다 — 렉서의 isNameStart). 그래서 `<txt>`의 오타는 여전히 "알 수 없는 태그"로
  잡히고 `a < b`만 통과한다. 선택지 3(공백만)은 같은 것을 더 좁게 하면서 규칙을 한 문장으로
  말할 수 없다.
- **`;`를 요구하는 이유**는 저자의 손해와 진단의 이득을 저울질한 결과다. XML 엄격(선택지 1)은
  `R&D`·`Q&A`·쿼리 문자열이 있는 링크를 전부 에러로 만든다 — 실무 덱의 산문에 흔한 문자이고,
  그 에러가 잡아 주는 실수는 없다(저자는 `&`를 쓰려고 `&`를 썼다). 반대로 `&nbsp;`처럼 **참조
  모양인데 어휘 밖**인 것은 저자가 참조를 의도한 것이 분명하므로 진단이 이득이다. `;`는 그 둘을
  가르는 정확한 신호다.
- **접기 → 풀기 순서**가 아니면 `&#32;`가 사라진다. 반대 순서에서는 푼 공백이 원문 공백과
  구별되지 않아 접기의 대상이 되고, 저자가 명시로 넣은 문자를 파서가 지운다. 파서가 U+00A0을
  건드리지 않는 근거와 같다.
- **역방향 호환은 검사해서 확인했다**: `testdata/fixtures/**/*.slide`와 `examples/**/*.slide`에
  `&`를 쓰는 곳이 없다 — 지금 `&lt;`를 리터럴 표기로 쓰는 덱은 없으므로 이 결정이 바꾸는
  산출물도 없다. 반대로 원문에 `&`를 리터럴로 쓰는 테스트는 있고(`R&D 로드맵 > 상반기`),
  `;` 요구 규칙이 그것을 그대로 통과시킨다.

## 결과

- `soml/charref.go`(신설): 참조 어휘 표와 `decodeCharData`(접기·풀기·진단을 한 번의 순회로).
  진단 구간은 `Span.Slice`로 원문 안의 참조를 정확히 가리킨다.
- `soml/lexer.go`: `startsMarkup` 규칙 + `TokenCData`/`TokenCDataUnterminated`.
  태그 **안**의 마크업 아닌 `<`는 `TokenInvalid`로 남는다 (지금처럼 lexContent로 넘기면
  텍스트 토큰이 태그를 삼킨다).
- `soml/parse.go`: 문자 데이터와 속성 값이 `decodeCharData`를 지난다. CDATA는 문자 데이터
  토큰과 같은 자리에서 처리되고, 닫히지 않은 CDATA는 진단이 된다.
- `render/web`·`render/pptx`: 변경 없음 — 두 경로 모두 이미 출력 경계에서 이스케이프한다.
  이 ADR은 그 경계가 **한 번만** 일어나는 것을 테스트로 고정한다.
- `docs/reference/soml/text-subset.md`: 문자 참조·CDATA 절.
- `examples/balpyo-intro`: 매핑 표를 실제 SOML 태그 문법으로 다시 쓴다.
