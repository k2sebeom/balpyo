# 0001 — 파서는 트리비아를 보존한다

- 상태: 확정
- 날짜: 2026-08-17
- Iteration: 0
- 관련: PRD §12.2, TASKS Iteration 0 "선결정 확정"

## 맥락

Iteration 0에서 필요한 명령은 `build`뿐이고, `build`는 **의미**만 필요하다 — 어떤
태그에 어떤 속성이 있는지. 공백을 두 칸 썼는지, 속성 값을 `'`로 감쌌는지, 주석을
어디에 달았는지는 렌더 결과에 영향이 없다. 그래서 렉서가 공백과 주석을 버리는 쪽이
지금 당장은 단순하다.

문제는 나중에 붙일 계획인 두 기능이다.

- `balpyo format` — 정규화된 SOML을 다시 쓴다. 원문을 복원할 수 없으면 포맷터는
  "다시 만들어 쓰기"가 되고, 주석이 사라지거나 위치가 옮겨진다.
- `balpyo lsp` — 편집 중인 문서는 **항상 깨져 있다.** 커서 위치의 토큰을 알아야
  자동완성을 낼 수 있고, 진단은 사람이 보는 좌표(line:col)를 가리켜야 한다.

두 기능 모두 "원문 조각과 그 위치"를 요구한다. 트리비아를 버린 토큰 열에는 그 정보가
없고, 나중에 되돌릴 수도 없다 — 렉서를 다시 쓰고 그 위에 쌓인 파서·검증기·에러 리포팅을
전부 손봐야 한다. PRD §12.2가 이것을 "나중에 붙일 수 없는 결정"으로 분류한 이유다.

## 선택지

1. **무손실 토크나이저를 처음부터 만든다.** 트리비아를 토큰으로 남기고, 파서는 읽을 때
   건너뛴다. `build`는 이득이 없고 토큰 종류가 늘어난다.
2. **버리는 렉서로 시작하고 format/lsp를 만들 때 교체한다.** 지금이 가장 단순하다.
   교체 시점에 렉서 위의 모든 층이 회귀 위험에 놓인다.
3. **두 렉서를 유지한다** — build용 빠른 렉서, 도구용 무손실 렉서. 같은 문법을 두 번
   구현하는 것이므로 둘이 갈라지는 순간 "에디터에서는 통과했는데 빌드가 깨진다"가 된다.

## 결정

**선택지 1 — 무손실 토크나이저를 처음부터 만든다.**

토큰 열의 계약은 실행 가능한 형태로 못 박혀 있다:

> `Tokenize(src)`가 낸 토큰의 `Text`를 순서대로 이어 붙이면 `src`와 **바이트 단위로 같다.**

`soml.Tokens.Source()`가 그 복원이고, 렉서 테스트가 모든 입력에 대해 이 등식을 검사한다.

따라오는 규칙:

- **트리비아는 종류로 구분한다.** `TokenWhitespace`(태그 내부 공백), `TokenComment`,
  `TokenCommentUnterminated`가 트리비아다 (`TokenKind.IsTrivia`). 파서는
  `Tokens.WithoutTrivia()`처럼 건너뛰며 읽는다.
- **요소 사이의 문자 데이터는 트리비아가 아니다.** `TokenText`의 공백은 텍스트 내용의
  일부다 — 트리비아로 분류하면 `<text>두 낱말</text>`의 공백이 의미에서 빠진다.
- **인용 부호는 토큰 `Text`에 남는다.** `id="a"`와 `id='a'`는 같은 의미지만 다른 원문이다.
  format의 무손실 조건이 이 구분을 요구한다.
- **렉서는 실패하지 않는다.** 문법에 맞지 않는 입력도 `TokenInvalid`,
  `TokenStringUnterminated`, `TokenCommentUnterminated`로 덮어 통과시키고 진단은 파서
  층이 낸다. 편집 중인 문서가 항상 깨져 있는 lsp를 전제한 설계이며, 무손실 계약이 깨진
  입력에서도 성립하게 한다.
- **닫히지 않은 문자열은 줄 끝에서 멈춘다.** 인용 부호 하나를 빠뜨린 문서가 파일 나머지
  전체를 문자열로 삼켜 진단이 엉뚱한 곳을 가리키는 일을 막는다.
- **위치는 `Pos{Offset, Line, Col}`이고 `Col`은 룬 기준이다.** 진단 메시지가 사람에게
  보이는 좌표계이므로 한글 한 글자가 세 칸으로 세어지면 안 된다. LSP가 요구하는 UTF-16
  변환은 lsp 층의 몫이다.

## 근거

- 되돌릴 수 없는 결정과 되돌릴 수 있는 결정을 구분하면, 되돌릴 수 없는 쪽에 미리 값을
  치르는 것이 싸다. 무손실 렉서의 추가 비용은 토큰 종류 몇 개와 "건너뛰며 읽기"뿐이다.
- 위치 정보는 `build`에도 이미 필요하다. PRD가 요구하는 "line/col을 가리키는 엄격한
  에러"는 트리비아 보존과 같은 자료구조에서 나온다 — 그래서 이 결정의 비용은 Iteration 0
  에서 이미 회수된다.
- 문법이 하나면 도구가 갈라지지 않는다. `build`·`check`·`format`·`lsp`가 같은 렉서를
  본다는 것은 "에디터에서 본 진단 = CI가 막는 진단"의 전제다.

## 결과

- `soml/lexer.go`, `soml/token.go`, `soml/position.go`가 이 계약을 구현한다.
- `soml.Tokens.Source()`가 무손실 계약의 실행 가능한 표현이고, 렉서 테스트가 그것을 검사한다.
- Iteration 1의 파서는 토큰 열 위에 올라가며 트리비아를 건너뛴다. 덱 모델에는 트리비아가
  없다 — 렌더러는 의미만 본다.
- `balpyo format`(Phase 2)은 새 렉서 없이 이 토큰 열 위의 정규화 층으로 만들어진다.
