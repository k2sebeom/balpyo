# 0040 — 프리셋의 텍스트 영역은 기하 표의 한 열이고, 그 표는 웹만 읽는다

- 상태: 확정
- 날짜: 2026-09-20
- 마일스톤: P1.2 (도형 프리셋의 텍스트 영역 — TASKS.md D5)
- 관련: PRD §7.5(도형 프리셋), §9.4(매핑 표), ADR 0016(도형 안 텍스트는 도형의 본문),
  ADR 0017(도형 기하는 OOXML 프리셋에서 유도한다), ADR 0019(radius),
  [shape.md](../../docs/reference/soml/shape.md)

## 맥락

`<shape>` 안의 텍스트는 두 타깃에서 **다른 자리에** 앉는다. 웹은 도형 박스 전체를 텍스트가
쓸 공간으로 보고(flex 열 + `pad`), PPTX는 프리셋의 **텍스트 영역**(`presetShapeDefinitions.xml`의
`<rect>`)을 쓴다 — PowerPoint·LibreOffice가 `prstGeom`마다 들고 있는 값이고 우리가 끄거나
바꿀 수단이 없다. 그래서 `<shape type="diamond">`에 한 줄을 담으면 웹은 마름모 박스의 왼쪽
변부터, LibreOffice는 안쪽 사각형(박스의 25%~75%)부터 글을 흘린다: 같은 SOML에서 줄바꿈 위치와
줄 수가 갈라진다.

이것은 ADR 0017이 열어 둔 채 닫은 구멍이다 — 그 결과 절이 이렇게 적어 두었다: "프리셋의 텍스트
rect는 구현하지 않았다 … 고치는 길은 기하 표에 열을 하나 더 유도하는 것이다." `testdata/fixtures/04_shape/001`과
`examples/balpyo-intro/004`는 그 구멍을 **회피하는 모양**으로 쓰여 있다 (라벨을 도형 밖 형제
`<text>`로 뺐다). 회피가 문서에 남으면 그것이 어휘의 사용법이 된다.

## 선택지

**표를 어디에 두는가**:

- (가) `soml`의 닫힌 카탈로그 — 프리셋 목록(`shapeTypes`) 곁.
- (나) `render/web`의 기하 유도표(`shapeGeometries`)에 열을 하나 더한다.

**누가 읽는가**:

- (다) 웹과 PPTX가 **같은 표**를 읽는다 (웹은 인셋, PPTX는 `bodyPr` 인셋).
- (라) 웹만 읽는다. PPTX는 프리셋이 네이티브로 적용하므로 아무것도 하지 않는다.

**웹이 백분율 인셋을 무엇으로 구현하는가**: 자기 박스의 크기를 모르는 채로(ADR 0017) 네 변에
박스 비례 인셋을 넣어야 한다 — `padding`/`margin` 백분율(네 변 모두 **부모 폭** 기준), 컨테이너
쿼리(`cqh`), 절대 배치 래퍼.

## 결정

**텍스트 영역은 (나) 기하 표의 한 열이고, (라) 웹만 읽는다. 값은 박스 백분율이며
rounded-rect 하나만 `radius` 비례 px이다. 웹은 백분율이 있는 프리셋에서 텍스트를 절대 배치
래퍼(`.balpyo-shape-body`)에 담고, 0인 프리셋은 지금 구조를 그대로 둔다.**

표 (박스 백분율, `shapeGeometry.TextRect`):

| type | preset | l | t | r | b | 유도 |
|---|---|---|---|---|---|---|
| rect | rect | 0 | 0 | 0 | 0 | rect = 박스 |
| rounded-rect | roundRect | \* | \* | \* | \* | 네 변 모두 `radius × (1 − √2/2)` **px** (모서리 원호에 내접) |
| ellipse | ellipse | 14.6447 | 14.6447 | 14.6447 | 14.6447 | 타원에 내접하는 사각형 = `(1 − √2/2)/2` |
| diamond | diamond | 25 | 25 | 25 | 25 | 마름모에 내접 (꼭짓점 중점 넷) |
| cylinder | can | 0 | 25 | 0 | 12.5 | 뚜껑 타원 전체(`2·y1`) 아래, 바닥 반타원(`y1`) 위 |
| chevron | chevron | 0 | 0 | 0 | 0 | `x1 = x2`로 rect가 붕괴 → 프리셋이 박스로 되돌린다 (아래 근거) |
| arrow-right | rightArrow | 0 | 25 | 25 | 25 | 축 띠(`y1`~`y2`)이고 오른쪽은 머리 시작(`x1`) |
| hexagon | hexagon | 16.6667 | 16.6667 | 16.6667 | 16.6667 | 사선 `u = ¼(1 − 2v)` 위의 등인셋 점 → `d = ⅙` |
| parallelogram | parallelogram | 18.75 | 18.75 | 18.75 | 18.75 | 기울기 `x2`(25%)의 ¾ |
| callout | wedgeRectCallout | 0 | 0 | 0 | 0 | 꼬리는 박스 밖이고 본문은 사각형 전체다 |
| star | star5 | 30.902 | 38.1968 | 30.902 | 23.6073 | 내부 오각형의 bbox (표에 있는 경로 좌표 그대로) |
| cloud | cloud | 13.78 | 15.10 | 20.89 | 19.74 | 프리셋 `rect`의 21600 공간 유리수 (`2977`·`3262`·`17087`·`17337`) |

- 백분율의 기준은 **도형 박스**(테두리 상자)이고, 저자의 `pad`는 이 영역 **안쪽**에 다시
  들어간다 (두 타깃 모두 — 아래 근거의 실측).
- 백분율이 하나라도 0이 아닌 프리셋(ellipse·diamond·cylinder·arrow-right·hexagon·
  parallelogram·star·cloud 8종)에서 `<shape>`가 텍스트를 담으면 **높이가 확정이어야 한다**
  (`h` 또는 `ratio`). 값 층이 진단한다.
- PPTX는 이 표를 읽지 않는다. `bodyPr`의 인셋은 계속 저자의 `pad`다 (항목 05 그대로).

## 근거

- **표가 `render/web`에 있는 이유는 이것이 어휘가 아니라 유도이기 때문이다.** 수치의 출처는
  프리셋 정의 하나이고(ADR 0017), 그 유도는 이미 경로 데이터·조정값 명세와 함께 한 표에 줄
  단위 주석으로 적혀 있다. 텍스트 영역을 `soml`에 두면 같은 프리셋의 수치가 두 파일로 갈라지고,
  프리셋을 하나 더할 때 한쪽만 채운 것이 **모양은 맞는데 글자만 어긋난 도형**으로 나타난다 —
  ADR 0017이 "열을 하나 더 유도하는 것"이라고 적어 둔 이유다. `soml`은 값 어휘를 소유하지만
  텍스트 영역에는 저자가 쓸 표기가 없다 (열려 있지 않은 값이다).
- **PPTX가 표를 읽으면 인셋이 두 번 들어간다.** 실측으로 확인했다: 프리셋마다 같은 도형을
  나란히 두고 웹 잉크와 LibreOffice 잉크의 첫 글자 위치를 재면, 차이가 곧 위 표의 값이다
  (400×400에서 diamond l 100px = 25.0%, hexagon 66px = 16.5%, star t 153px = 38.25%). 즉
  LibreOffice는 우리가 아무것도 적지 않아도 프리셋 rect를 적용하고 있고, `bodyPr`에 같은 값을
  또 실으면 PPTX 쪽만 두 배로 들어간다. `pad="md"`를 더한 실행이 같은 차이를 그대로 재현한
  것도 같은 사실의 다른 면이다 — `pad`는 양쪽에서 rect **안쪽에** 더해지므로 저자의 `pad`를
  `bodyPr`에 싣는 지금 매핑이 이미 맞다.
- **그래서 "같은 표를 읽는다"는 보장은 테스트로 옮긴다.** TASKS의 선결정은 웹 인셋과 `bodyPr`
  인셋이 한 표를 읽게 하라고 적었지만, 실제 불변식은 "두 타깃에서 글자가 같은 자리에 온다"다.
  한쪽이 값을 코드로 넣지 않는다면 표를 공유할 자리가 없으므로, 대신 **프리셋 12종의 웹 잉크와
  LibreOffice 잉크를 견주는 픽셀 테스트**가 그 보장을 진다. 그 테스트는 표가 틀렸을 때도
  깨지므로 표를 공유하는 것보다 강하다 (공유는 두 벌이 같다는 것만 보장한다).
- **`chevron`이 0인 것은 프리셋의 성질이다.** 우리는 정규 공간을 늘리므로 PPTX 조정값이
  `adj = 50000·w/ss`가 되고(ADR 0017), 짧은 변이 `h`인 가로 도형에서 이 값은 `maxAdj`에
  걸린다 — 그러면 프리셋의 `x1`과 `x2`가 만나 rect의 폭이 0이 되고 LibreOffice는 박스 전체로
  되돌린다. 실측이 rect와 정확히 같은 값을 준 것이 그 확인이다. 표에 0을 적는 것은 "이 프리셋은
  텍스트 영역이 없다"가 아니라 **"우리가 내는 chevron에서는 박스가 텍스트 영역이다"**의 기록이다.
- **백분율이 박스 종횡비와 무관한 이유**도 같은 데서 온다: 조정값 보정 덕분에 어느 비율에서도
  실루엣이 박스를 같은 비율로 나누므로, 텍스트 영역도 박스의 고정 비율이다. 400×400·560×320·
  320×560 세 번의 측정이 모든 프리셋에서 ±0.3% 안으로 일치했다 (cylinder t: 100/400, 80/320,
  140/560 = 25.0%). 백분율 표가 맞는 표현이라는 증거이고, 웹이 백분율 기하로 구현할 수 있다는
  뜻이다.
- **rounded-rect만 px인 이유**는 `radius`가 px이기 때문이다 (ADR 0019·0017: 반경은 테마·저자가
  준 px이고 늘림 없는 px 공간에 산다). 모서리 원호 안에 내접하는 사각형의 인셋은
  `r − r/√2 = 0.29289r`이고, 실측이 `radius=12`에서 3~4px(예측 3.51), `radius=32`에서
  9~10px(예측 9.37)이다.
- **절대 배치 래퍼를 고른 이유**: CSS `padding`/`margin`의 백분율은 네 변 모두 **부모의 인라인
  크기**를 기준으로 하므로 세로 인셋을 표현할 수 없다 (마름모의 위 25%가 폭의 25%가 된다).
  `container-type: size` + `cqh`는 자기 높이를 참조할 수 있지만 **내용이 높이를 정하는 것을
  금지하는 것은 절대 배치와 똑같고**, 컨테이너 쿼리 쪽은 높이가 확정되지 않았을 때 값이 조용히
  0이 된다. 절대 배치는 같은 제약을 **눈에 보이게** 실패한다: 높이가 확정되지 않은 도형은
  그림(`.balpyo-shape-ink`)까지 함께 0이 되므로 도형 자체가 사라진다 — 조용한 어긋남보다 낫고,
  값 층 진단이 그 자리를 먼저 막는다.
- **높이를 요구하는 것이 실제로 옳은 규칙이다.** 실루엣 프리셋에서 내용이 높이를 정하면 도형은
  "글자에 꼭 맞는 마름모"가 되고 그 안의 텍스트 영역은 내용보다 작으므로, 글자는 **반드시**
  실루엣을 가로지른다. 즉 이 조합은 진단 없이도 언제나 사고다. `soml`은 이미 도형에 크기를
  요구하는 태도를 문서화해 두었다 (ShapeAttrs 주석: "도형은 그 자체가 그림이다").
- **0인 프리셋의 구조를 바꾸지 않는 이유**는 골든의 뜻이다. rect·chevron·callout은 값이 0이므로
  래퍼를 넣어도 결과가 같은데, 넣으면 세 프리셋의 픽셀이 (서브픽셀 반올림 때문에) 흔들리고
  그 변화는 이 항목과 무관하다. 가장 많이 쓰이는 프리셋(카드 = `rect`·`rounded-rect`)에서
  DOM 구조가 그대로인 것이 리뷰 갤러리의 신호 대 잡음비를 지킨다.

## 결과

- `render/web/shape.go`: `shapeGeometry`에 `TextRect` 열(`shapeTextRect{L,T,R,B,Radius}`)과
  12행의 값·유도 주석. `ShapeTextRect(type)`를 내보내 테스트가 표를 견줄 수 있게 한다.
  `writeShape`는 백분율이 있는 프리셋에서 `.balpyo-shape-body` 래퍼를 쓰고(`left`/`top`/
  `right`/`bottom` 백분율, `pad`가 래퍼로 옮겨 간다), rounded-rect는 패딩에 `0.29289·radius`
  px을 더한다. `shapeCSS`에 래퍼의 엔진 CSS 한 규칙.
- `core`: 백분율 인셋 프리셋 + 텍스트 자식 + 확정 높이 없음 → 에러 진단.
- `render/pptx`: 변경 없다 (이 ADR의 절반은 "PPTX는 아무것도 하지 않는다"는 기록이다).
- `testdata/fixtures/04_shape`: 프리셋 12종 × 도형 안 텍스트 픽스처. 웹/LibreOffice 잉크 대조가
  이 표의 회귀 테스트다. `001_shape_types.slide`의 "라벨은 도형 밖" 주석이 사라진다.
- `examples/balpyo-intro/004`: chevron 라벨이 도형 안으로 돌아온다 (이 항목의 검수 증거).
- `docs/reference/soml/shape.md`: 프리셋별 텍스트 영역 표와 높이 요구.
