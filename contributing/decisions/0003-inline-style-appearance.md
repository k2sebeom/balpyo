# 0003 — 요소 외관은 인라인 `style` 속성으로 낸다

- 상태: 확정
- 날짜: 2026-08-18 (결정은 Iteration 1의 웹 렌더러 구현에서)
- Iteration: 1
- 관련: PRD §5.3 (두 개의 선언 채널), §7.9 (`style` 탈출구), §9.4

## 맥락

`core.Resolve`가 확정한 텍스트 외관(크기·굵기·줄높이·색·폰트·정렬)을 웹 렌더러가 HTML로
내야 한다. 기본 CSS는 cascade layer로 `balpyo.base < balpyo.theme < balpyo.author`
순서를 선언해 두었고, 저자 CSS는 author 층에서 **배치**를 조정할 수 있어야 한다
(Iteration 3의 `style` 탈출구 — 배치 전용, 외관 CSS는 경고).

문제는 확정된 외관을 어디에 실을 것인가다. 외관은 스키마에서 양 타깃으로 순방향
컴파일된다는 계약이 있으므로, 웹에서 외관이 저자 CSS에 덮이면 **웹만 바뀌고 PPTX는 그대로**
인 상태 — 두 산출물을 나란히 보기 전까지 드러나지 않는 갈라짐 — 가 생긴다.

## 선택지

1. **인라인 `style` 속성.** 확정 값을 요소마다 `style="font-size: 64px; …"`로 낸다.
   인라인 선언은 모든 cascade layer 위에 있으므로(`!important` 없이는 못 덮는다) 저자
   CSS가 외관을 못 건드린다.
2. **`data-balpyo-id` 선택자로 생성 규칙.** `<style>` 블록에
   `[data-balpyo-id="s0.1"] { font-size: 64px; }` 같은 규칙을 요소 수만큼 생성한다.
   HTML이 깔끔해지지만 규칙이 layer 안에 있어 author 층이 이길 수 있고, 요소와 외관이
   문서의 두 곳으로 갈라져 사람이 산출물을 읽을 때 대조가 필요하다.
3. **역할별 클래스** (`balpyo-text--title`). 역할 기본값을 CSS로 되살리려면 core의
   기본값 표를 렌더러에 한 번 더 적어야 하고, 그 이중화가 두 타깃의 외관이 갈라지는
   경로다. 인라인 속성(`size="64"`)은 어차피 클래스로 표현할 수 없다.

## 결정

**선택지 1 — 인라인 `style` 속성.** (`render/web.writeText` → `textStyleCSS`)

값은 전부 명시한다 — 상속으로 채워지는 값이 하나라도 있으면 기본 CSS를 고칠 때 텍스트
메트릭이 조용히 움직이고, 지오메트리 패스가 잰 박스가 곧 PPTX 박스이므로 그 움직임이
산출물까지 간다. 색·폰트는 리터럴이 아니라 테마 변수 참조(`var(--balpyo-color-*)`)로
낸다 — 인라인이지만 테마 편집은 따라간다.

## 근거

- **외관 불변이 구조로 보장된다.** 인라인 선언은 layer 순서와 무관하게 이기므로, "저자
  CSS는 배치만 만진다"는 규칙(PRD §7.9)이 관례가 아니라 CSS 우선순위로 강제된다.
- **외관의 원천이 하나로 보인다.** 요소를 보면 확정 외관이 그 자리에 있다 — 산출물을
  읽는 사람과 지오메트리 패스가 대조할 문서 위치가 하나다.
- 선택지 2를 버린 이유: layer 안의 규칙은 author 층이 덮을 수 있어 외관 채널의 경계가
  CSS 지식에 의존하게 되고, 생성 규칙 수천 개는 산출물 크기와 가독성 모두에서 이득이 없다.

## 결과

- `render/web/content.go`(writeText), `render/web/style.go`(textStyleCSS)가 구현이다.
- 저자가 외관을 바꾸는 길은 SOML 속성과 (Iteration 10의) 테마뿐이다 — 의도된 제약이다.
