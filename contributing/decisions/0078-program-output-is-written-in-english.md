# 0078 — 프로그램이 내는 글은 영어로 쓴다

- 상태: 확정
- 날짜: 2026-10-10
- 관련: [cli.md](../../docs/reference/cli.md), [AGENTS.md](../../AGENTS.md)

## 맥락

지금까지 문서 · ADR · 주석과 함께 **진단도 한국어**로 썼다. 그래서 `balpyo`가 터미널에 내는 거의 모든
글 — 파서 · `core.Validate`의 진단, 렌더러 · 파이프라인의 에러, `build`/`check`/`watch`의 요약, 사용법,
`init`이 만드는 덱, 뷰어 · 검수 갤러리의 안내 — 이 한국어였다. 이 저장소의 주 언어는 영어여야 하고,
CLI의 출력은 그 도구를 쓰는 모든 사람이 읽는 표면이다.

## 선택지

1. **그대로 둔다.** 한국어를 읽지 못하는 사용자는 진단을 읽을 수 없다.
2. **출력을 영어로 바꾸고 문서 · ADR · 주석은 한국어로 둔다.** 사용자가 보는 표면만 바꾼다.
3. **출력을 i18n으로 고르게 한다.** 문구가 두 벌이 되고, 골든 · 문서 게이트 · 테스트 기댓값이 언어마다
   갈린다. 진단이 "한 곳에서" 나온다는 불변식이 메시지 카탈로그로 흩어진다.

## 결정

**선택지 2.** 프로그램이 내는 글은 영어로 쓴다: 진단, 에러, CLI 출력과 사용법, `init` 템플릿(덱 언어
기본값 `en`), 생성물에 실리는 CSS 주석, 뷰어 · watch 오버레이 · 검수 갤러리의 문구, 테스트 하네스의
실패 문구, Makefile의 출력. 문서 · ADR · 코드 주석은 한국어로 둔다. 문서가 진단을 인용할 때는 실제
영어 문구를 그대로 인용한다.

## 근거

- 진단은 **한 곳에서** 나오므로(파서와 `core.Validate`) 언어를 바꾸는 것은 문구를 바꾸는 일이지 구조를
  바꾸는 일이 아니다. 문구의 회귀는 각 패키지의 기댓값과 `golden/diagnostics.txt`가 이미 잡는다.
- 문서 게이트(`core/docs_test.go`)는 문서에 인용된 진단 안의 닫힌 목록을 읽으므로, 문서가 실제 문구를
  인용하는 한 게이트는 그대로 일한다.
- 언어를 하나만 내면 i18n의 비용(문구 두 벌, 골든 두 벌) 없이 모든 사용자가 읽을 수 있다.

## 결과

- `golden/diagnostics.txt`, 문서의 진단 인용, 문서 게이트의 패턴이 영어 문구로 바뀐다.
- 진단 문구를 바꾸는 규칙(그 입력을 픽스처로 남긴다)은 그대로다.
- 요약 줄의 수량은 영어 단수 · 복수로 쓴다 (`1 slide`, `3 slides`).
- 측정용 표본 글(`EastAsianSample`)처럼 출력이 아닌 한국어 리터럴은 남는다.
