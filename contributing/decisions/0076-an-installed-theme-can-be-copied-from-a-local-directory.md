# 0076 — 설치한 테마는 로컬 디렉토리에서 **복사**해 올 수도 있다

- 상태: 확정 (0075의 설치 출처에 로컬 디렉토리를 더한다)
- 날짜: 2026-10-09
- 관련: [ADR 0075](0075-an-installed-theme-is-a-name-the-theme-declares-under-balpyo-home.md)(설치한 테마는
  `~/.balpyo`에 사는 이름이다), [CLI](../../docs/reference/cli.md), [테마 패키지](../../docs/reference/theme.md)

## 맥락

0075는 설치의 출처를 GitHub 공개 저장소 하나로 열었다. 그런데 테마를 만드는 사람은 먼저 자기 기계의
디렉토리에서 테마를 고치고, 회사 테마는 사내 Git 서버·공유 드라이브·비공개 저장소의 체크아웃에 있는
경우가 흔하다 (0075가 "열지 않은 것"으로 남긴 비공개 저장소·GitHub 밖의 호스트가 그것이다). 그 테마를
여러 덱에서 쓰려면 지금은 덱마다 `themes/<이름>/`으로 복사하는 길뿐이다 — 0075가 없애려던 바로 그 일이다.

질문은 셋이다: **설치가 원본을 복사하는가 가리키는가**, **경로와 GitHub 주소를 어떻게 가르는가**,
**출처를 무엇으로 기록하는가**.

## 선택지

**(1) 설치한 테마와 원본의 관계**

- (가) 홈에 심볼릭 링크를 둔다 — 원본을 고치면 곧바로 보인다.
- (나) **복사한다** — 홈의 테마는 원본과 떨어진 사본이다.

**(2) 인자를 가르는 법**

- (가) 별도 플래그(`--path`)나 명령(`install-local`).
- (나) **같은 `install` 인자 하나**: `/`·`./`·`../`·`~/`로 시작하면(또는 `.`·`..`·`~`) 언제나 경로,
  그 밖에는 GitHub 주소로 읽고, 주소가 아니면서 있는 디렉토리면 경로.

**(3) 출처 기록**

- (가) 기록하지 않는다 (손으로 넣은 디렉토리와 같다).
- (나) **`themes.json`에 디렉토리의 절대 경로(`local`)와 그 안의 테마 경로(`path`)를 적는다.**

## 결정

1. **(1)은 (나)다.** 로컬 설치는 GitHub 설치와 같은 길을 간다 — 임시 디렉토리에 복사하고, `theme.json`이
   있는 디렉토리를 모두 후보로 찾고(`.` 디렉토리는 보지 않고 복사하지도 않는다), 이름·`extends` 부모를
   같은 규칙으로 고르고, 옮긴 뒤 로드해 보고, 실패하면 되돌린다. 정규 파일과 디렉토리만 복사하고 링크는
   따라가지 않는다 — 테마 안의 링크는 GitHub 설치와 같은 에러다.
2. **(2)는 (나)다.** 경로 모양이 먼저이므로 `github.com/acme/x`라는 디렉토리가 있어도 주소의 뜻은 바뀌지
   않는다. 주소도 디렉토리도 아니면 에러가 `./<인자>`로 적으라고 말한다.
3. **(3)은 (나)다.** 경로는 `~`를 펼치고 절대 경로로, 심볼릭 링크를 푼 모양으로 적는다.
   `balpyo theme update`는 그 디렉토리에서 다시 복사한다. 같은 디렉토리·같은 테마 경로에서 다시 설치하는
   것은 갈아 끼우기가 아니다(`--force` 불필요). GitHub에서 설치한 같은 이름(또는 그 반대)은 다른 출처다.
4. **홈은 복사하지 않는다.** 홈을 담은 디렉토리를 가리켜도 복사가 자기 자신을 담지 않는다.

## 근거

**왜 링크가 아니라 복사인가.** 0075의 설치는 "이 기계의 사실"이고 빌드는 홈만 읽는다. 링크를 두면 홈의
테마가 원본의 상태에 매인다 — 원본 디렉토리를 옮기거나 브랜치를 바꾸면 덱이 말없이 다른 테마로 빌드되거나
멈춘다. 그리고 설치가 하는 검사(로드 가능·이름·링크 없음)는 설치하는 순간의 사실이라 링크 뒤의 파일이
바뀌면 그 검사가 무의미해진다. 복사하면 이 두 성질이 GitHub 설치와 같고, 고친 것을 반영하는 길은 이미 있는
`update`다. 고치는 중의 테마를 곧바로 보고 싶다면 그 자리는 프로젝트의 `themes/<이름>/`이다.

**왜 같은 인자인가.** 사람이 붙여 넣는 것은 주소이거나 경로이고, 둘은 모양으로 갈린다. 플래그를 두면
"주소처럼 생긴 경로"라는 드문 경우를 위해 흔한 경우가 한 단어를 더 친다. 드문 경우는 `./`로 못박는다.

**왜 출처를 적는가.** 적지 않으면 `update`가 할 일이 없고, 같은 디렉토리에서 다시 설치할 때마다
`--force`가 필요해진다 — 로컬 테마는 GitHub 테마보다 자주 고쳐지는 테마다.

## 결과

- **`internal/themestore`**: `Source.Dir`(로컬 출처), `ResolveSource`·`LocalSource`, 복사(`copyDir`),
  `Record.Local`·`HasOrigin`. 찾기·고르기·옮기기·되돌리기는 GitHub 설치와 같은 코드다.
- **`cmd/balpyo`**: `balpyo theme install <GitHub 주소 | 경로>`. `list`가 경로를 출처로 보인다.
- **문서**: `reference/cli.md`, `reference/theme.md`, `guides/theming.md`.
- 0075의 "열지 않은 것"(비공개 저장소·GitHub 밖의 호스트)은 여전히 직접 받지 않는다 — 체크아웃한 디렉토리를
  로컬 출처로 설치하는 길이 생겼을 뿐이다.
