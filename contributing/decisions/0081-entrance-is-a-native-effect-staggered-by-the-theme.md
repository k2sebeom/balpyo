# 0081 — 등장은 두 타깃의 원어 효과이고, 엇갈림은 테마가 정한다

- 상태: 확정
- 날짜: 2026-10-10
- 관련: [ADR 0063](0063-reveal-is-presenter-only-hiding-and-every-other-target-is-flattened.md)(`reveal`은
  발표자 뷰에서만 숨긴다), [ADR 0021](0021-measure-view-disables-transforms.md)(측정 뷰는 변형을 끈다),
  [ADR 0064](0064-the-contract-is-component-and-layout-parity-not-pixel-parity.md), 백로그 Q10

## 맥락

손으로 짠 HTML 덱은 거의 모든 요소가 슬라이드에 들어올 때 떠오르기 · 페이드 · 확대로 **엇갈려**
나타난다. SOML의 모션은 `<li reveal>` 하나 — 발표자 뷰에서 클릭으로 하나씩 보이는 것 — 뿐이다.

PowerPoint에는 원어가 있다: 슬라이드의 `p:timing`에 등장 효과(`presetClass="entr"`)를 걸면 애니메이션
창에 효과가 나열되고, "이전 효과와 함께" + 지연이 엇갈림이다. 효과는 도형마다 걸린다.

## 선택지

1. **웹 전용 모션**으로 두고 PPTX는 정적으로 평탄화한다 (`reveal`과 같은 태도). PPTX 사용자는 원본
   덱의 절반을 잃는다.
2. **두 타깃의 원어 효과**로 연다 — 두 타깃에 다 있는 효과만.
3. 임의의 CSS 애니메이션을 연다. PPTX로 옮길 곳이 없다.

엇갈림 간격의 자리: 저자 속성(장마다 다른 박자) 또는 테마(덱의 박자 하나).

## 결정

**선택지 2, 박자는 테마.**

1. **`enter` 속성**이 콘텐츠 요소(`<text>` · 블록 · 리스트 · 레이아웃 컨테이너 · `<shape>` · `<image>` ·
   `<table>` · `<chart>`)에 열린다. 값은 `fade` · `rise` · `zoom` · `wipe` · `none`이다.
   `<slide enter="…">`는 **직속 자식마다** 같은 값을 준 것과 같다 (자식이 자기 `enter`를 쓰면 그것이
   이긴다 — `none`으로 끌 수 있다).
2. **한 번의 등장 = `enter`를 가진 요소 하나**이고, 그 요소의 PPTX 객체 전부(자손 도형 · 글상자 · 그림)가
   함께 등장한다. 객체는 **가장 가까운** `enter` 조상의 등장에 속한다 — `enter`를 가진 요소 안에 다시
   `enter`가 있으면 안쪽이 따로 등장한다. 등장의 순서는 그 요소들의 문서 순서다.
3. **자동이다** — 슬라이드가 시작되면 첫 등장이 테마의 `delay` 뒤에, 그다음부터 `stagger` 간격으로
   시작한다. 클릭 단계는 이 결정 밖이다 (`reveal`은 그대로 리스트 항목의 클릭 단계다).
4. **박자는 테마의 `tokens.json` `motion`**이다: `duration` · `stagger` · `delay`(ms). 테마가 `motion`을
   정하지 않았는데 덱이 `enter`를 쓰면 에러다.
5. **효과 대응**:

   | `enter` | 웹 (발표자 뷰) | PPTX |
   |---|---|---|
   | `fade` | 투명 → 불투명 | 페이드 (`presetID=10`, `animEffect filter="fade"`) |
   | `rise` | 페이드 + 아래 24px에서 제자리로 | 떠오르기 (`presetID=42`, 페이드 + `ppt_y` 이동) |
   | `zoom` | 페이드 + 90%에서 100%로 | 확대 (`presetID=53`, 페이드 + `ppt_w`·`ppt_h`) |
   | `wipe` | 왼쪽에서 오른쪽으로 드러남 (`clip-path`) | 닦아내기 (`presetID=22`, `animEffect filter="wipe(left)"`) |

6. **숨기는 곳은 웹의 발표자 뷰 하나다** (ADR 0063과 같다). 문서 뷰 · 측정 뷰 · 오버뷰 · 인쇄는 끝 상태를
   본다 — 측정한 배치는 `enter`를 쓰기 전과 한 픽셀도 다르지 않다. `prefers-reduced-motion`이면 웹은
   움직이지 않는다.
7. **패리티 트리에 등장이 나온다**: 슬라이드마다 등장 순서대로 (효과 · 지연 · 대상 객체 이름) 한 줄씩.

## 근거

- **효과를 넷으로 닫는 이유**는 두 타깃의 교집합이다: 넷 다 PowerPoint의 기본 등장 효과이고 웹에서
  CSS 전환 하나로 같은 모양이 된다. 날아오기 · 회전 같은 효과는 웹에서 크기 · 경로가 갈라진다.
- **박자를 테마에 두는 이유**는 엇갈림이 덱의 리듬이라는 것이다 — 장마다 다른 박자는 의도가 아니라
  사고로 읽힌다. 크기 · 색 · 자간을 테마가 갖는 것과 같은 자리다.
- **가장 가까운 조상**으로 묶는 이유: PPTX에서 효과는 도형마다 걸린다. 컨테이너는 도형이 되지 않으므로
  (ADR 0011) 컨테이너의 등장은 그 자손 객체들이 **함께** 등장하는 것이다 — 웹에서 컨테이너 하나가
  나타나는 것과 같은 그림이다.
- **자동으로 시작하는 이유**: 참조 덱의 모션은 전부 슬라이드 진입에 묶여 있고, 클릭 단계는 이미
  `reveal`이 있다. 둘을 한 타임라인으로 합치는 것은 그 필요가 실물로 나올 때 한다.

## 결과

- 확정 모델에 등장(`Appearance.Enter`)이 실리고, 슬라이드마다 등장 계획(순서 · 지연 · 객체)이 렌더러에
  닿는다. 계획을 만드는 규칙은 한 곳(core)에 있다.
- PPTX 슬라이드에 `p:timing`이 생긴다 (등장이 없는 슬라이드에는 없다 — 바이트가 그대로다).
- 웹 런타임이 슬라이드에 들어갈 때 등장을 켠다. JS가 없으면 끝 상태로 열린다.
