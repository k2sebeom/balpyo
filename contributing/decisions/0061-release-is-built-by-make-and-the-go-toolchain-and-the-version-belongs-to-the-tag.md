# 0061 — 릴리스는 **make와 Go 툴체인**이 만들고 버전은 **태그**가 소유한다 (goreleaser를 쓰지 않는다)

- 상태: 확정
- 날짜: 2026-09-21
- 마일스톤: P6 (배포)
- 관련: PRD §10(바이너리 하나가 모든 서브커맨드를 담는다), ADR 0048(`init`은 자기 덱을 소유하고
  `check`는 쓰지 않는 `build`다), ADR 0056(게이트는 잡이 아니라 **테스트**로 늘린다),
  ADR 0047(리뷰 갤러리는 `internal/preview`가 소유하고 명령과 테스트가 그것을 함께 쓴다),
  [릴리스](../internals/release.md), [CLI](../../docs/reference/cli.md),
  [테스트 전략](../internals/testing.md)

## 맥락

P6은 "저자가 이 도구를 **받는** 방법"이다. 지금 받는 길은 저장소를 체크아웃해 `go build`하는
것뿐이고, 그 바이너리는 자기가 어느 커밋에서 나왔는지 사람이 읽을 수 있게 말하지 않는다:

```
$ balpyo version
balpyo v0.0.0-20260921012736-feda13ce5d78
```

의사 버전(pseudo-version)에 날짜와 짧은 커밋이 들어 있기는 하다 — 그러나 버그 리포트에 붙는
줄로서는 세 가지를 말하지 않는다: 태그(사람이 아는 이름), 트리가 **더러웠는지**, 어느
OS/아키텍처에서 돈 바이너리인지.

### 실측 — `go build`는 이미 커밋을 박는다

주입(`-ldflags -X`) 없이 빌드한 바이너리의 빌드 정보를 읽었다:

```
$ go build -trimpath -o balpyo ./cmd/balpyo && go version -m balpyo
	build	-trimpath=true
	build	CGO_ENABLED=0
	build	vcs=git
	build	vcs.revision=feda13ce5d780470789b86c378272d543d8ac60d
	build	vcs.time=2026-09-21T01:27:36Z
	build	vcs.modified=false
```

세 가지가 여기서 갈렸다:

- **커밋·시각·더러움은 주입할 값이 아니다.** 툴체인이 `vcs.*`에 박고 `-trimpath`도 그것을
  지우지 않는다. 릴리스 스크립트가 `git rev-parse`를 불러 `-X`로 넣으면 **같은 사실의 두 번째
  출처**가 생긴다 (그리고 그 출처는 스크립트를 거치지 않은 빌드에서 조용히 빈다).
- **`go test -c`로 만든 바이너리에는 `vcs.*`가 없다** (실측: `vcs.` 줄 0개). 그래서 버전 문자열의
  테스트는 "커밋이 있다"를 요구할 수 없다 — 형식과 **주입이 이긴다**는 규칙만 판정하고, 박힌
  커밋을 보는 판정은 진짜 바이너리를 빌드해서 한다.
- **태그만이 우리가 아는 이름이다.** `v0.3.0`은 저장소 밖의 사실(어느 아카이브를 받았는지)이므로
  주입이 필요한 값은 그것 하나다.

### 실측 — 크로스 컴파일은 한 줄이고 재현된다

CGO가 없으므로(`"C"` import 0건) 네 타깃이 환경 변수 둘로 끝난다:

```
$ time (for p in linux/amd64 linux/arm64 darwin/amd64 darwin/arm64; do
    GOOS=… GOARCH=… CGO_ENABLED=0 go build -trimpath -o … ./cmd/balpyo; done)
real	0m40.052s      # 찬 캐시에서 네 타깃
21564001  balpyo-linux-amd64     20194905  balpyo-linux-arm64
22063168  balpyo-darwin-amd64    20836610  balpyo-darwin-arm64
```

그리고 같은 커밋에서 두 번 빌드한 바이너리는 **바이트까지 같다**:

```
bb1a1fe93e7246fe7517ed23f83ab9748b95273727b245ba89bd55c3ba6a5db1  a
bb1a1fe93e7246fe7517ed23f83ab9748b95273727b245ba89bd55c3ba6a5db1  b
```

40초·20MB·바이트 동일. 이 숫자가 아래 선택지를 갈랐다.

## 선택지

1. **goreleaser** — `.goreleaser.yaml` 하나로 아카이브·체크섬·릴리스 노트·Homebrew tap 커밋까지
   한다. 사실상의 표준이다.
2. **make + Go 툴체인** — 크로스 컴파일 루프를 우리가 돌리고, 아카이브·체크섬·포뮬러도 우리가
   만든다.
3. **쉘 스크립트** (`scripts/release.sh`) — 2의 변형. 절차가 쉘에 산다.

## 결정

1. **릴리스는 make와 Go 툴체인이 만든다** (선택지 2). goreleaser를 쓰지 않는다.
2. **릴리스 절차는 Go 코드이고, 테스트가 그것을 판정한다** — `internal/release`가 플랫폼 표,
   아카이브 이름, 체크섬 파일, Homebrew 포뮬러, 그리고 `-ldflags` 문자열을 **한 자리에서**
   소유한다. `make dist`는 `go run ./internal/release/cmd`를 부르는 한 줄이다 (선택지 3을 버리는
   이유: 쉘에 든 절차는 테스트가 읽지 않는다 — ADR 0056의 "게이트는 잡이 아니라 테스트다"와
   `internal/preview`의 선례가 같은 자리에 있다).
3. **플랫폼 표는 넷이다**: `darwin/arm64` · `darwin/amd64` · `linux/amd64` · `linux/arm64`.
   윈도우는 **열지 않는다** — 근거는 없음이 아니라 **재보지 않았음**이다 (경로 구분자·CRLF·폰트
   대체·`soffice` 위치를 한 번도 측정하지 않았고, 측정하지 않은 플랫폼의 아카이브를 놓는 것은
   "빌드된다"를 "된다"로 발표하는 일이다).
4. **버전은 태그가 소유하고 커밋은 툴체인이 소유한다.** 릴리스 빌드는 `-X …main.version=<태그>`
   하나만 주입하고, 커밋·시각·더러움은 `debug.ReadBuildInfo()`의 `vcs.*`에서 읽는다. 주입도
   `vcs`도 없으면 모듈 버전이고, 그것마저 없으면 `(devel)`이다.
5. **`balpyo version`은 세 줄이다** — 이름·버전 / 커밋·시각 / 플랫폼·툴체인:

   ```
   balpyo v0.3.0
   커밋 feda13c (2026-09-21T01:27:36Z)
   linux/amd64 · go1.26
   ```

   더러운 트리는 커밋 줄이 그렇게 말한다 (`feda13c+dirty`). 아는 것만 적는다 — 커밋을 모르는
   빌드는 그 줄이 없다 (`알 수 없음`을 찍으면 리포트에 쓸모없는 줄이 하나 늘 뿐이다).
6. **아카이브는 `balpyo_<버전>_<os>_<arch>.tar.gz` 하나 형식이고 체크섬은 `SHA256SUMS` 한 파일**
   이다. 아카이브에는 바이너리와 `LICENSE`·`README` 대신 **바이너리 하나만** 넣는다 (PRD §10의
   "바이너리 하나"를 아카이브 안에서도 지킨다 — 저자가 `tar xf` 후 찾을 것이 하나다).
7. **Homebrew tap은 생성물이고 발행은 사람의 것이다.** `make dist`가 체크섬에서
   `dist/balpyo.rb`를 만들고, tap 저장소(`homebrew-balpyo`)에 그 파일을 올리는 것은 릴리스
   워크플로가 **하지 않는다** — 우리 저장소가 아닌 곳에 쓰는 토큰을 CI에 두지 않는다.
8. **태그가 릴리스를 트리거하고, 릴리스는 게이트를 다시 돈다.** `.github/workflows/release.yml`은
   `v*` 태그에서 컨테이너 테스트(`make test`)를 통과한 뒤에만 아카이브를 올린다. 발표한
   아티팩트는 되돌릴 수 없으므로 3분을 다시 쓴다.
9. **재현성은 계약이다**: `CGO_ENABLED=0` · `-trimpath` · 주입 값은 태그 하나. 같은 태그에서 두 번
   빌드하면 같은 바이트가 나와야 하고, 그 사실을 테스트가 한 타깃에서 판정한다.

## 근거

- **goreleaser를 쓰지 않는 근거는 환경의 단일성이다.** 이 저장소의 모든 게이트는 컨테이너
  하나와 make 타깃 하나를 지난다 (CI가 로컬과 같은 것을 돈다 — `docs/internals/testing.md`).
  릴리스만 다른 설정 언어·다른 버전 핀·다른 실행 방식을 들이면 "환경이 하나"가 깨지고, 릴리스가
  깨졌을 때 재현할 곳이 로컬에 없다. 얻는 것은 위 실측이 말한다: 우리가 대신 쓸 코드는 루프
  하나와 tar 하나다.
- **절차를 Go에 두는 근거는 `internal/preview`의 선례다** (ADR 0047): 사람이 쓰는 명령과 테스트가
  **같은 코드**를 쓰면 "테스트가 본 것과 사람이 받은 것"이 갈라질 수 없다. 플랫폼 표가 쉘 루프에
  있으면 타깃 하나를 지우는 커밋을 아무 테스트도 보지 못한다.
- **버전의 출처를 하나로 두는 근거는 낡음의 방향이다.** 커밋을 `-X`로 주입하면 스크립트를 거친
  빌드만 커밋을 알고, `go install`로 받은 바이너리는 그 자리를 빈 문자열로 둔다 — 리포트에서
  가장 필요한 줄이 가장 조용히 빈다.
- **`+dirty`를 찍는 근거는 리포트다.** 저자가 자기 트리에서 빌드해 쓰는 일이 흔한 단계이므로,
  "이 바이너리는 커밋된 나무가 아니다"가 버전 줄에 없으면 우리가 재현할 수 없는 보고를 받는다.
- **윈도우를 미루는 근거는 ADR 0056과 같다.** 예제 게이트가 "경고 0"을 요구하는 이유가 "제품이 쓴
  문서는 제품의 주장"이라는 것이었다. 발표한 아카이브도 주장이다 — 재보지 않은 플랫폼의 주장을
  놓지 않는다.

## 결과

**열리는 것**

- `make dist`가 네 아카이브 + `SHA256SUMS` + `dist/balpyo.rb`를 낸다 (`dist/`는 산출물이므로
  커밋하지 않는다).
- `balpyo version`이 버그 리포트에 그대로 붙일 수 있는 세 줄이 된다.
- `v*` 태그가 GitHub Releases를 만든다 — 사람이 하는 일은 태그를 밀고, tap 저장소에 생성된
  포뮬러를 올리는 것 둘이다.

**닫히는 것 (근거가 생기면 다시 연다)**

- **윈도우 아카이브** — 그 플랫폼에서 빌드·실행을 재고 나서 표에 한 줄 더한다.
- **goreleaser·릴리스 노트 자동 생성** — 노트는 사람이 쓴다 (커밋 메시지가 릴리스 노트가 아니다).
- **tap 자동 커밋** · **패키지 매니저 확장**(scoop·apt·nix) · **서명·공증**(macOS
  `codesign`/notarytool — 키를 CI에 두는 결정이 따로 필요하다).
- **도커 이미지 배포** — 테스트 이미지는 게이트의 것이고 사용자의 것이 아니다.
