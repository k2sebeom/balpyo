# 0015 — `fill`은 해당 축의 100%다 (`grow`와 겹치지 않는다)

- 상태: 확정
- 날짜: 2026-08-20
- Iteration: 3 (항목 02 — NOTES.md 03/02가 근거 기록이다)
- 관련: PRD §7.4 (컨테이너·자식 속성 표),
  [레이아웃 태그](../../docs/reference/soml/layout.md)

## 맥락

PRD §7.4의 컨테이너 표는 크기 속성(`w`/`h`/`min-w`/`min-h`/`max-w`/`max-h`)의 값으로
`수치·%·fill`을 적는다. `fill`이 CSS의 무엇으로 컴파일되는지는 정해져 있지 않았고, 두 읽기가
가능했다 — "축을 가득 채운다"(`100%`)와 "남은 공간을 받는다"(`flex-grow: 1`). 같은 표의 자식
속성에는 `grow`가 이미 `flex-grow`로 있다.

## 선택지

1. **`fill` = `100%`.** 값 층에서 백분율 100으로 눕히고, 렌더러는 `width: 100%`를 낸다.
2. **`fill` = `flex-grow: 1`.** 주축에서 남은 공간을 받는다.
3. **`fill`을 별도 상태로 남긴다.** `soml.Length`에 `LengthFill` 같은 세 번째 상태를 두고
   렌더러가 문맥(주축인가 교차축인가, flex인가 grid인가)을 보고 CSS를 고른다.

## 결정

**선택지 1 — `fill`은 해당 축의 100%다.** 값 층에서 `Percent(100)`으로 눕고, 확정 값에
`fill`이었다는 흔적을 남기지 않는다.

## 근거

- **같은 결과를 내는 표기가 둘이 되는 것을 막는다.** 선택지 2를 고르면 `w="fill"`과
  `grow="1"`이 flex 주축에서 같은 뜻이 되고, 저자가 어느 것을 써야 하는지에 답이 없다.
  게다가 두 표기의 시맨틱은 **교차축과 grid에서 갈라진다** — `grow`는 주축의 남은 공간
  분배이고 `100%`는 축의 크기다. 이름이 둘, 뜻이 하나였다가 문맥에서 갈라지는 것이 가장
  가르치기 어려운 종류의 어휘다.
- **선택지 3을 버린 이유는 두 렌더러가 갈라질 자리다.** 문맥 판단이 렌더러에 있으면 웹이
  내는 CSS와 (앞으로) 다른 소비자가 읽는 값이 어긋날 수 있고, 무엇보다 문맥 판단은 부모의
  흐름·축을 아는 코드를 렌더러에 새로 만든다. 값 층이 한 번만 눕히면 확정 값에 상태가 하나뿐이다
  (`soml.Appearance`의 계약 — 렌더러는 확정 값만 읽는다).
- **`basis`에 `fill`을 열지 않은 것도 같은 결정의 일부다.** PRD 표에서 `fill`은 크기 속성의
  값이고, `flex-basis: 100%`는 주축에서만 크기가 되어 교차축에서 저자의 기대와 갈라진다.
  백분율이 필요하면 `basis="100%"`로 적는다 — 그 표기에는 애매함이 없다.

## 결과

- `w="fill"`은 웹에서 `width: 100%`가 된다. `03_layout/005_sizing` 픽스처가 그 산출을
  골든으로 고정한다.
- 진단이 `fill`을 어디에 쓸 수 있는지 말한다: 크기 속성은 `수치·백분율·fill`,
  `gap`/`pad`는 `수치·백분율·공간 토큰`. `gap="fill"`은 "알 수 없는 공간 토큰"이다.
- 확정 값에 `fill`의 흔적이 없으므로 `w="fill"`과 `w="100%"`는 산출물에서 구별되지 않는다 —
  의도된 손실이다 (공간 토큰이 이름을 남기는 것과 반대인 이유: 토큰은 테마를 따라가야 하는
  **참조**이고, `fill`은 표기의 축약일 뿐이다).
