# 0079 — 자간과 대소문자는 테마의 타이포그래피이고, 런은 작아지거나 형광펜을 받을 수 있다

- 상태: 확정
- 날짜: 2026-10-10
- 관련: [ADR 0008](0008-run-style-inherit-copy.md)(인라인 런은 확정 스타일의 상속-복사다),
  [ADR 0005](0005-line-spacing-and-slack.md)(줄간격은 spcPts), [외관 속성](../../docs/reference/appearance.md),
  백로그 Q7

## 맥락

손으로 짠 HTML 덱을 SOML로 옮기면 글자 서식 넷이 막힌다.

1. **자간** — 키커(`AWS COMPUTE FUNDAMENTALS`)는 0.16em 벌린 글자다. 텍스트 외관에 자간이 없다.
2. **대문자 변환** — 같은 키커가 대문자다. 원고에 대문자로 쓰면 PPTX에서 편집할 때 원문이 사라지고,
   테마를 바꿔도 대문자가 남는다 — 대문자는 원고가 아니라 디자인의 것이다.
3. **런 크기** — `750+`처럼 큰 수 뒤의 작은 단위. `<span>`은 색·굵기만 받는다: 파서가 `size`를
   막았고, 근거는 "런이 커지면 웹 줄 박스가 커지는데 PPTX 줄간격은 문단 절대값(`spcPts`)이라 글줄이
   갈라진다"였다.
4. **형광펜** — 정의 문장의 핵심 구절 아래 칠한 색 띠.

넷 다 OOXML에 원어가 있다: `a:rPr@spc`(1/100pt), `a:rPr@cap="all"`, `a:rPr@sz`, `a:rPr/a:highlight`
(`CT_Color` — `schemeClr`을 받는다).

## 선택지

자간·대소문자의 자리:

1. **저자 속성** (`<text tracking="0.16" case="upper">`) — 어휘가 넓어지고, 덱마다 키커의 자간이
   달라진다.
2. **테마 필드** — 역할 · 컴포넌트 기본값 · variant가 `tracking`·`case`를 가진다. 저자는 `variant`
   이름만 쓴다.

런 크기:

1. 계속 막는다.
2. **블록보다 작거나 같은 크기만** 연다.
3. 아무 크기나 연다.

형광펜의 색:

1. 저자 속성 (`<mark color>`).
2. **테마가 소유한다** (`text.mark.highlight`).

## 결정

1. **`tracking`·`case`는 테마 필드다.** `components.json`의 `text.roles` · `componentDefaults` ·
   `variants`가 둘 다 선택적으로 받는다. 저자 속성으로는 열지 않는다.
   - `tracking`은 **글자 크기의 배수**(em)다. 범위는 −0.1 ~ 0.5이다. 웹 `letter-spacing: <n>em`,
     PPTX `a:rPr@spc` = round(n × 크기px × 0.75 × 100) (1/100pt — 크기가 확정된 뒤 타깃 경계에서
     환산한다. 줄높이를 배수로 들고 있다가 `spcPts`로 바꾸는 것과 같은 자리다).
   - `case`는 `upper` · `none` 둘이다. 웹 `text-transform: uppercase`, PPTX `a:rPr@cap="all"`.
     **원문은 그대로 남는다** — 두 산출물의 글자 데이터는 저자가 쓴 대소문자이고 대문자는 표시
     속성이다.
   - 둘 다 정하지 않으면 아무 선언도 나가지 않는다 — 이 필드를 쓰지 않는 테마의 산출물은 바이트가
     같다.
2. **`<span size>`를 연다 — 감싼 블록의 크기 이하만.** 블록보다 큰 값은 에러다. 작은 런은 블록의
   줄 박스 안에 들어가므로 웹 줄 높이가 블록의 `line-height`로 정해지고, PPTX의 문단 절대 줄간격과
   같은 높이를 유지한다 — 막았던 근거(커진 런이 줄을 민다)가 이 범위에서는 성립하지 않는다.
3. **`<mark>`를 인라인 태그로 더한다.** 형광펜 색은 테마의 `text.mark.highlight`(색 문법 — 토큰,
   변형)이고 `<mark>`는 속성을 받지 않는다. 웹은 런의 `background-color`, PPTX는 `a:highlight`다.
   테마가 형광펜을 정하지 않았는데 덱이 `<mark>`를 쓰면 에러다 (조용한 기본색이 없다).
4. 패리티 트리의 런 줄에 `tracking=<n>` · `upper` · `mark=<색>`이 **정했을 때만** 붙는다.

## 근거

- **자간과 대문자는 디자인 시스템의 것이다.** 키커가 키커처럼 보이는 이유는 덱의 모든 키커가 같은
  자간·같은 대소문자이기 때문이다. 저자 속성으로 열면 장마다 다른 값이 생기고, 테마를 바꿀 때 원고를
  고쳐야 한다. 크기·굵기·색이 이미 variant로 테마에 있는 것과 같은 자리다.
- **대문자를 표시 속성으로 두는 이유**는 편집 가능성이다: PowerPoint에서 `cap="all"`인 글자를
  고치면 원문 대소문자로 편집되고, 테마를 갈면 대문자가 사라진다. 원고를 대문자로 쓰면 둘 다 잃는다.
- **런 크기를 "작은 쪽"으로만 여는 이유**: 원래 막은 근거는 줄 박스의 증가였다. 작은 런은 블록의
  스트럿 안에 앉아 줄 박스를 키우지 않는다 — 열어도 계약(같은 글줄 높이)이 깨지지 않는 쪽만 연다.
  큰 런은 여전히 같은 근거로 막힌다.
- **형광펜 색을 테마가 소유하는 이유**는 강조색이 팔레트이기 때문이다 (코드 토큰 색을 저자가 고르지
  않는 것과 같은 근거). 테마가 정하지 않으면 에러인 이유는 "기본 테마가 없다"는 결정과 같다 — 어느
  색으로도 조용히 칠하지 않는다.

## 결과

- `soml.TextStyle`에 `Tracking`·`Case`·`Highlight`가 생긴다. 인라인 런은 상속-복사로 이 셋을 물려받고,
  `<mark>`만 `Highlight`를 얹는다.
- 내장 테마 셋과 예제 테마의 `kicker` variant가 자간·대문자를 얻는다 — 그 variant를 쓰는 예제 덱의
  산출물이 바뀐다.
- `<mark>`는 어휘의 네 층(soml 카탈로그 · core · 두 렌더러)에 같은 커밋으로 들어간다.
