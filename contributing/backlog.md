# 백로그

아직 하지 않은 일의 목록이다. **순서는 정하지 않았다** — 집어 들 때 정한다. 구현된 동작은
[레퍼런스](../docs/reference/index.md)에, 계약을 바꾸는 결정은 [ADR](decisions/index.md)에 있다.
여기 있는 것은 어느 쪽에도 아직 없다.

항목을 끝내면 이 목록에서 지운다 — 끝난 일의 기록은 커밋 로그와 ADR이 맡는다.

## 품질 — 손으로 짠 HTML 덱 수준 (Q)

기준은 손으로 짠 단일 HTML 덱 하나다 ("What is Amazon EC2?", 13장, 1920×1080, 저장소 밖에
있다). 타이포·카드·그림자·그라디언트 글자·크롬은 지금 테마로 닿는다. 닿지 않는 것은 **도식**
(상태 기계·아키텍처·등축 스택·곡선 차트)과 **모션**(엇갈린 등장·선 그리기·슬라이드 전환)이다.

목표는 그 덱을 SOML로 옮겨 **웹과 편집 가능한 PPTX 둘 다** 같은 수준으로 내는 것이다. 계약은
그대로다 — 같은 요소가 같은 종류의 객체로, 잰 rect에, 같은 확정 외관으로, 같은 순서로 나간다.
그래서 각 항목은 **OOXML에 편집 가능한 원어가 있는 것**부터 연다 (그림으로 굽지 않는다). 원어가
없는 것(Q13)만 웹 전용으로 남기고, 그 사실을 진단이 말한다.

식별자(Q1…)는 커밋 로그가 그대로 쓰므로 유지한다. "선행"은 순서가 아니라 의존이다.

### Q2 — 자유 경로 `<path>` (사용자 지오메트리)

- **막힌 것**: 곡선·계단·등축 면처럼 프리셋에 없는 모양을 그릴 수 없다. 도형 어휘를 OOXML
  프리셋으로 닫은 결정(ADR 0017)이 경계다.
- **방향**: 박스 기준 정규 좌표의 경로 데이터(`d`, 직선·3차 베지어·닫기만 — 호는 베지어로
  풀거나 뺀다). 박스 크기·위치는 지금처럼 배치가 정하고 경로는 그 박스로 늘어난다.
  웹은 `<svg viewBox>` 경로, PPTX는 `a:custGeom`의 `a:pathLst`(점 단위로 편집 가능).
  채움·테두리·그라디언트·그림자·불투명도는 도형 외관 그대로다.
- **ADR**: 필요 — ADR 0017을 대체한다 (프리셋은 기본이고 `path`는 열린 출구). 경로 문법의 닫힌
  부분집합, 정규 공간 vs px 공간, 열린 경로(선)와 닫힌 경로(면)의 채움 규칙.
- **끝난 기준**: 열린/닫힌/곡선 경로 픽스처 패리티, XSD 통과, Q4가 이 위에 선다.

### Q3 — 프리셋 확장

- **막힌 것**: 12종으로는 Nitro 스택(등축 상자)·삼각형·도넛·호·더하기 같은 흔한 도식 부품이
  없다. 대부분 OOXML 프리셋에 이미 있다.
- **방향**: ADR 0017의 기준(프리셋 정의에서 웹 경로를 유도) 안에서 목록만 넓힌다. 후보:
  `cube`(등축 층), `triangle`, `donut`, `block-arc`, `plus`, `pentagon`(`homePlate`),
  `plaque`, 괄호(`left-bracket`·`right-brace` — 회전으로 아래 괄호가 된다), 순서도 몇 종. `cube`는 윗면·옆면이 `lighten`/`darken` 채움 수정자를 쓰므로 웹이 같은
  음영 규칙을 재현해야 한다. 조정값(`adj`, 예: 큐브 깊이)을 열지는 여기서 정한다.
- **ADR**: 조정값을 저자에게 열면 필요, 목록만 넓히면 불필요.
- **끝난 기준**: 새 프리셋마다 픽스처 + 웹 실루엣이 정의에서 유도됨을 보이는 테스트, 참조 덱
  6장의 층 스택을 `cube`로 재현.

### Q4 — 차트 확장 (선·영역·계단·산점·다계열)

- **막힌 것**: `<chart>`는 단일 계열 세로 막대뿐이다. 참조 덱 3장(곡선 + 계단 + 채움 영역)과
  9장(축·눈금·점·점선)은 막대가 아니다.
- **방향**: 지금처럼 **도형과 글로 풀어 쓴다** (ADR 0059 — 네이티브 차트 파트가 아니다).
  `type`에 `line` · `area` · `step` · `scatter`, 다계열(`<series>`), 축 제목·눈금선, 범례,
  점 주석(라벨 + 지시선 — 연결선을 쓴다), 부드러운 곡선(`smooth`). 선과 영역은 Q2의 경로로 푼다.
  빗금 채움은 OOXML `a:pattFill`이 있으니 채움 문법에 `pattern(…)`을 여는 것도 함께 본다.
- **ADR**: 필요 — 계열 색이 프레임에 속한다는 결정(ADR 0060)을 다계열로 넓히는 규칙, 축 범위
  자동/명시, 패턴 채움을 연다면 그 문법.
- **선행**: Q2.
- **끝난 기준**: 종류별 픽스처 패리티, 참조 덱 3·9장 재현.

### Q8 — SVG 그림

- **막힌 것**: 그림은 PNG·JPEG뿐이다(ADR 0025). 아키텍처 아이콘 세트는 SVG로 배포되고, 래스터로
  바꾸면 확대 시 흐려진다.
- **방향**: 웹은 SVG를 그대로, PPTX는 `a:blip` 안의 `asvg:svgBlip` 확장 + PNG 대체 그림(이미 있는
  헤드리스 브라우저가 잰 크기 × 배율로 래스터화). 결정성을 위해 래스터화 결과도 같은 입력 →
  같은 바이트여야 한다.
- **ADR**: 필요 — ADR 0025를 대체, 대체 PNG의 해상도 규칙, SVG 안의 스크립트·외부 참조 거부.
- **끝난 기준**: SVG 그림 픽스처, XSD + 패키지 검증 통과(확장 네임스페이스 포함), 결정성 테스트.

### Q9 — 크롬 소품: 전체 쪽수와 진행 막대

- **막힌 것**: 쪽번호에 전체 쪽수(`03 / 13`)와 0 채움을 쓸 수 없다. 웹 뷰어에 진행 막대가 없다.
- **방향**: 쪽번호 크롬 선언에 형식(`{n} / {total}`, 자릿수). PPTX는 `slidenum` 필드 뒤에 전체
  쪽수를 굽는다 (전체는 필드가 아니다 — 슬라이드를 지우면 낡는다는 사실을 레퍼런스에 적는다).
  진행 막대는 뷰어 런타임의 것이고 색은 테마 토큰이다. PPTX에는 대응이 없고 필요도 없다 (뷰어 크롬).
- **ADR**: 형식 문법이 생기면 짧게.
- **끝난 기준**: 픽스처 + 뷰어 테스트.

### Q13 — 웹 전용 상시 모션

- **막힌 것**: 아키텍처 장의 "흐르는" 점선(marching ants)과 맥박 점은 PPTX에 원어가 없다.
- **방향**: 둘 중 하나를 ADR로 고른다 — (가) 연결선 외관의 `flow`/도형의 `pulse`를 웹 전용 외관으로
  열고 `style` 탈출구처럼 **경고**한다, (나) PPTX에서 가까운 것(`pulse` ↔ 반복 강조 효과
  `repeatCount="indefinite"`)이 있는 것만 열고 `flow`는 PPTX에서 정적 점선으로 평탄화한다.
  어느 쪽이든 측정·인쇄·오버뷰에서는 멈춘다.
- **ADR**: 필요.

### Q14 — 참조 덱 이식과 게이트

- **할 일**: (1) 참조 덱을 `workspace/`에 SOML로 옮겨 각 항목이 끝날 때마다 다시 빌드하는
  현장 시험 — AWS 아이콘은 저장소에 커밋하지 않는다. (2) 같은 어휘를 다 쓰는 **커밋 가능한**
  예제 덱 하나(일반 도식, 자체 그림)와 그 덱의 테마를 `examples/`에 더해 엄격 무경고 게이트에
  올린다 (ADR 0056). (3) 끝나면 `make showcase`로 README 쇼케이스를 갱신한다.
- **끝난 기준**: `balpyo check --check-layout --strict`가 두 덱에서 무경고, `make qa`에서 웹 |
  OnlyOffice가 참조 덱과 같은 구성으로 읽힌다 (픽셀 비교가 아니라 눈으로 — ADR 0064), PPTX를
  PowerPoint에서 열어 연결선을 끌면 따라오고 애니메이션 창에 효과가 나열된다.
