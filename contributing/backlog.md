# 백로그

아직 하지 않은 일의 목록이다. **순서는 정하지 않았다** — 집어 들 때 정한다. 구현된 동작은
[레퍼런스](../docs/reference/index.md)에, 계약을 바꾸는 결정은 [ADR](decisions/index.md)에 있다.
여기 있는 것은 어느 쪽에도 아직 없다.

항목을 끝내면 이 목록에서 지운다 — 끝난 일의 기록은 커밋 로그와 ADR이 맡는다.

## 품질 — 손으로 짠 HTML 덱 수준 (Q)

기준은 손으로 짠 단일 HTML 덱 하나다 ("What is Amazon EC2?", 13장, 1920×1080, 저장소 밖에
있다). 타이포·카드·그림자·그라디언트 글자·크롬은 지금 테마로 닿는다. 닿지 않는 것은 **도식**
(상태 기계·아키텍처·등축 스택·곡선 차트)과 **모션**(엇갈린 등장·선 그리기·슬라이드 전환)이다.

목표는 그 덱을 SOML로 옮겨 **웹과 편집 가능한 PPTX 둘 다** 같은 수준으로 내는 것이다. 계약은
그대로다 — 같은 요소가 같은 종류의 객체로, 잰 rect에, 같은 확정 외관으로, 같은 순서로 나간다.
그래서 각 항목은 **OOXML에 편집 가능한 원어가 있는 것**부터 연다 (그림으로 굽지 않는다). 원어가
없는 것(Q13)만 웹 전용으로 남기고, 그 사실을 진단이 말한다.

식별자(Q1…)는 커밋 로그가 그대로 쓰므로 유지한다. "선행"은 순서가 아니라 의존이다.

### Q1 — 연결선 `<connector>` (도식의 뼈대)

- **막힌 것**: 상자와 상자를 잇는 선이 없다. 상태 기계·아키텍처·흐름도가 전부 여기서 멈춘다.
  `<shape id>`는 이미 어휘에 있고 중복 검사를 받지만 아무것도 참조하지 않는다 — 첫 참조자가 된다.
- **방향**: 두 도형(`id`)을 잇는 요소. 경로는 `straight` · `elbow` · `curved`, 양 끝 화살촉,
  `border`와 같은 선 문법(굵기·`dashed`·색 토큰), 붙는 면(`top`/`end`/…, 생략 시 자동),
  끝 표식(화살촉·점 — `a:tailEnd type="triangle"|"oval"`).
  - 웹: 두 rect 사이의 SVG 경로. 단 웹 HTML은 지오메트리 패스 **전에** 렌더되므로 끝점을 어디서
    얻는지가 이 항목의 핵심 결정이다 — (가) 측정 뒤 웹을 한 번 더 렌더해 경로를 굽는다 (연결선은
    흐름 배치에 자리를 차지하지 않으므로 두 번째 렌더가 배치를 바꾸지 않는다), (나) 뷰어 런타임이
    DOM의 rect로 그린다 (JS 없이 열면 선이 없다). PPTX와 같은 끝점 계산을 공유하려면 (가)다.
  - PPTX: `p:cxnSp` + `a:stCxn`/`a:endCxn`(도형 id·연결점 idx) + `straightConnector1` ·
    `bentConnector3` · `curvedConnector3` + `a:headEnd`/`a:tailEnd`. PowerPoint에서 상자를 끌면
    선이 따라온다 — 그림이 아니라 진짜 연결선이다.
  - 선 라벨(`reboot`, `terminate`)은 연결선이 글을 담지 못하므로 경로 중점에 놓는 별도 글상자다.
- **ADR**: 필요 — 새 종류, `id`의 첫 산출(PPTX `cNvPr@name`/웹 속성), 연결점 대응(프리셋별
  연결점 목록은 `presetShapeDefinitions`에서), 라벨 배치, 연결선이 흐름 배치에 자리를 차지하지
  않는다는 것(측정 대상이 아니라 측정 결과에서 유도된다), 잇는 도형이 다른 슬라이드·없는 id일 때의
  진단.
- **끝난 기준**: 픽스처(직선·꺾임·곡선·점선·화살촉·라벨) 패리티 + XSD 통과, 참조 덱 10·11장을
  `make qa`에서 웹과 OnlyOffice가 같은 도식으로 보여준다.

### Q2 — 자유 경로 `<path>` (사용자 지오메트리)

- **막힌 것**: 곡선·계단·등축 면처럼 프리셋에 없는 모양을 그릴 수 없다. 도형 어휘를 OOXML
  프리셋으로 닫은 결정(ADR 0017)이 경계다.
- **방향**: 박스 기준 정규 좌표의 경로 데이터(`d`, 직선·3차 베지어·닫기만 — 호는 베지어로
  풀거나 뺀다). 박스 크기·위치는 지금처럼 배치가 정하고 경로는 그 박스로 늘어난다.
  웹은 `<svg viewBox>` 경로, PPTX는 `a:custGeom`의 `a:pathLst`(점 단위로 편집 가능).
  채움·테두리·그라디언트·그림자·불투명도는 도형 외관 그대로다.
- **ADR**: 필요 — ADR 0017을 대체한다 (프리셋은 기본이고 `path`는 열린 출구). 경로 문법의 닫힌
  부분집합, 정규 공간 vs px 공간, 열린 경로(선)와 닫힌 경로(면)의 채움 규칙.
- **끝난 기준**: 열린/닫힌/곡선 경로 픽스처 패리티, XSD 통과, Q4가 이 위에 선다.

### Q3 — 프리셋 확장

- **막힌 것**: 12종으로는 Nitro 스택(등축 상자)·삼각형·도넛·호·더하기 같은 흔한 도식 부품이
  없다. 대부분 OOXML 프리셋에 이미 있다.
- **방향**: ADR 0017의 기준(프리셋 정의에서 웹 경로를 유도) 안에서 목록만 넓힌다. 후보:
  `cube`(등축 층), `triangle`, `donut`, `block-arc`, `plus`, `pentagon`(`homePlate`),
  `plaque`, 괄호(`left-bracket`·`right-brace` — 회전으로 아래 괄호가 된다), 순서도 몇 종. `cube`는 윗면·옆면이 `lighten`/`darken` 채움 수정자를 쓰므로 웹이 같은
  음영 규칙을 재현해야 한다. 조정값(`adj`, 예: 큐브 깊이)을 열지는 여기서 정한다.
- **ADR**: 조정값을 저자에게 열면 필요, 목록만 넓히면 불필요.
- **끝난 기준**: 새 프리셋마다 픽스처 + 웹 실루엣이 정의에서 유도됨을 보이는 테스트, 참조 덱
  6장의 층 스택을 `cube`로 재현.

### Q4 — 차트 확장 (선·영역·계단·산점·다계열)

- **막힌 것**: `<chart>`는 단일 계열 세로 막대뿐이다. 참조 덱 3장(곡선 + 계단 + 채움 영역)과
  9장(축·눈금·점·점선)은 막대가 아니다.
- **방향**: 지금처럼 **도형과 글로 풀어 쓴다** (ADR 0059 — 네이티브 차트 파트가 아니다).
  `type`에 `line` · `area` · `step` · `scatter`, 다계열(`<series>`), 축 제목·눈금선, 범례,
  점 주석(라벨 + 지시선 — Q1의 선을 쓴다), 부드러운 곡선(`smooth`). 선과 영역은 Q2의 경로로 푼다.
  빗금 채움은 OOXML `a:pattFill`이 있으니 채움 문법에 `pattern(…)`을 여는 것도 함께 본다.
- **ADR**: 필요 — 계열 색이 프레임에 속한다는 결정(ADR 0060)을 다계열로 넓히는 규칙, 축 범위
  자동/명시, 패턴 채움을 연다면 그 문법.
- **선행**: Q2 (Q1은 주석에만).
- **끝난 기준**: 종류별 픽스처 패리티, 참조 덱 3·9장 재현.

### Q5 — 슬라이드 단위 배경과 색 반전

- **막힌 것**: 배경은 테마의 **레이아웃별** 선언뿐이다(ADR 0073). 참조 덱 13장처럼 `content`
  레이아웃인데 어두운 장을 덱 중간에 둘 수 없고, 어두운 배경에서 `fg`/`bg` 토큰이 뒤집히지 않는다.
- **방향**: 슬라이드가 테마의 이름 붙은 배경·색 매핑을 고른다 (예: `<slide variant="dark">`).
  PPTX는 슬라이드의 `p:bg` + `p:clrMapOvr`(bg1↔tx1 교체 — 토큰이 이름으로 남는 불변식과 맞는다),
  웹은 그 슬라이드에서 CSS 변수를 다시 선언한다. 원고에는 색이 아니라 이름만 남는다.
- **ADR**: 필요 — 슬라이드 variant의 범위(배경만인가, 색 매핑까지인가), 레이아웃 배경과의 우선순위.
- **끝난 기준**: 반전 장이 섞인 픽스처 패리티, 반전 장 안의 `color="fg"` 글자가 두 타깃에서 밝다.

### Q6 — 배경 겹치기와 방사형 그라디언트

- **막힌 것**: 배경 선언은 `fill`과 `image` 중 **하나**다. 표지(사진 + 가로 그라디언트 덮개 +
  모서리 광채)를 만들 수 없다. `gradient(…)`는 선형뿐이다.
- **방향**: 배경을 겹(layer) 목록으로 연다 — 맨 아래 하나만 `p:bg`에 가고 나머지는 레이아웃의
  전면 도형(잠긴 장식)으로 간다. 그라디언트에 방사형(`radial-gradient` ↔ `a:gradFill` +
  `a:path path="circle"` + `a:fillToRect`)과 투명 스톱(`alpha()`)을 연다 — 덮개는 "불투명 → 투명"
  선형이다. 배경 그림의 자리 맞춤(`cover`·초점)도 같이 본다.
- **ADR**: 필요 — 배경 겹의 계약(어디까지 `p:bg`이고 어디부터 도형인가), 방사형 문법.
- **끝난 기준**: 겹 배경·방사형 픽스처 패리티, 참조 덱 1장 재현.

### Q8 — SVG 그림

- **막힌 것**: 그림은 PNG·JPEG뿐이다(ADR 0025). 아키텍처 아이콘 세트는 SVG로 배포되고, 래스터로
  바꾸면 확대 시 흐려진다.
- **방향**: 웹은 SVG를 그대로, PPTX는 `a:blip` 안의 `asvg:svgBlip` 확장 + PNG 대체 그림(이미 있는
  헤드리스 브라우저가 잰 크기 × 배율로 래스터화). 결정성을 위해 래스터화 결과도 같은 입력 →
  같은 바이트여야 한다.
- **ADR**: 필요 — ADR 0025를 대체, 대체 PNG의 해상도 규칙, SVG 안의 스크립트·외부 참조 거부.
- **끝난 기준**: SVG 그림 픽스처, XSD + 패키지 검증 통과(확장 네임스페이스 포함), 결정성 테스트.

### Q9 — 크롬 소품: 전체 쪽수와 진행 막대

- **막힌 것**: 쪽번호에 전체 쪽수(`03 / 13`)와 0 채움을 쓸 수 없다. 웹 뷰어에 진행 막대가 없다.
- **방향**: 쪽번호 크롬 선언에 형식(`{n} / {total}`, 자릿수). PPTX는 `slidenum` 필드 뒤에 전체
  쪽수를 굽는다 (전체는 필드가 아니다 — 슬라이드를 지우면 낡는다는 사실을 레퍼런스에 적는다).
  진행 막대는 뷰어 런타임의 것이고 색은 테마 토큰이다. PPTX에는 대응이 없고 필요도 없다 (뷰어 크롬).
- **ADR**: 형식 문법이 생기면 짧게.
- **끝난 기준**: 픽스처 + 뷰어 테스트.

### Q10 — 등장 애니메이션 (모든 요소, 엇갈림)

- **막힌 것**: 모션은 `<li reveal>`(발표자 뷰의 클릭 단계)뿐이다(ADR 0063). 참조 덱은 거의 모든
  요소가 슬라이드에 들어올 때 떠오르기·페이드·확대로 **자동으로 엇갈려** 나타난다.
- **방향**: 블록·도형·그림·컨테이너에 등장 효과(`fade` · `rise` · `zoom` · `wipe`)와 순서. 형제는
  자동으로 한 박자씩 밀린다 (테마가 박자·곡선·길이를 소유한다). 클릭 단계는 `reveal`을 이
  어휘로 넓혀 같은 축 위에 둔다 — "자동(이전 뒤)"과 "클릭"이 한 타임라인이다.
  - 웹: 뷰어 런타임이 슬라이드 진입 시 클래스로 트리거하는 CSS 전환. **측정·오버뷰·인쇄 뷰는 끝
    상태**다 (ADR 0021의 측정 뷰가 변형을 끄는 것과 같은 자리). `prefers-reduced-motion`이면 끈다.
  - PPTX: `p:timing`의 등장 효과(`presetClass="entr"`) — `afterPrev`/`onClick` 노드와 지연. 효과는
    PowerPoint 애니메이션 창에서 그대로 편집된다.
- **ADR**: 필요 — ADR 0063을 넓히거나 대체, 효과 어휘(두 타깃에 다 있는 것만), 엇갈림의 소유자,
  패리티 계약에 효과·트리거·순서·지연을 넣는다(컴포넌트 트리의 일부가 된다).
- **끝난 기준**: 픽스처의 `layout.txt`에 효과가 나오고 PPTX에서 되읽은 타임라인과 같다,
  `p:timing` XSD 통과 + 뮤테이션 테스트, 기하 패스 결과가 애니메이션 유무와 무관함을 보이는 테스트.

### Q11 — 선 그리기

- **막힌 것**: 참조 덱의 도식 선은 스스로 그려진다 (stroke-dashoffset).
- **방향**: 연결선·열린 경로에 `draw` 등장 효과. 웹은 `pathLength=1` + dashoffset 전환, PPTX는
  선 방향에 맞춘 `wipe` 등장 효과(가장 가까운 원어 — 곡선을 따라가지는 않는다는 차이를 레퍼런스의
  알려진 차이에 적는다).
- **선행**: Q1 또는 Q2, Q10.
- **끝난 기준**: 픽스처 패리티(효과·방향), 참조 덱 3·10장.

### Q12 — 슬라이드 전환

- **막힌 것**: 장을 넘길 때 전환이 없다. 참조 덱은 짧은 페이드 + 수평 이동이다.
- **방향**: 테마가 기본 전환(`fade` · `push` · 없음 + 길이)을 소유하고 슬라이드가 덮어쓴다.
  웹은 뷰어 런타임(오버뷰·인쇄·측정에서는 없음), PPTX는 `p:transition`(`p:fade`/`p:push dir`,
  길이는 `p14:dur` 확장 + `spd` 대체).
- **ADR**: 필요 — 소유자(테마 vs 덱 vs 슬라이드)와 어휘.
- **끝난 기준**: 픽스처 패리티, XSD 통과(확장 포함).

### Q13 — 웹 전용 상시 모션

- **막힌 것**: 아키텍처 장의 "흐르는" 점선(marching ants)과 맥박 점은 PPTX에 원어가 없다.
- **방향**: 둘 중 하나를 ADR로 고른다 — (가) 연결선 외관의 `flow`/도형의 `pulse`를 웹 전용 외관으로
  열고 `style` 탈출구처럼 **경고**한다, (나) PPTX에서 가까운 것(`pulse` ↔ 반복 강조 효과
  `repeatCount="indefinite"`)이 있는 것만 열고 `flow`는 PPTX에서 정적 점선으로 평탄화한다.
  어느 쪽이든 측정·인쇄·오버뷰에서는 멈춘다.
- **ADR**: 필요.
- **선행**: Q1, Q10.

### Q14 — 참조 덱 이식과 게이트

- **할 일**: (1) 참조 덱을 `workspace/`에 SOML로 옮겨 각 항목이 끝날 때마다 다시 빌드하는
  현장 시험 — AWS 아이콘은 저장소에 커밋하지 않는다. (2) 같은 어휘를 다 쓰는 **커밋 가능한**
  예제 덱 하나(일반 도식, 자체 그림)와 그 덱의 테마를 `examples/`에 더해 엄격 무경고 게이트에
  올린다 (ADR 0056). (3) 끝나면 `make showcase`로 README 쇼케이스를 갱신한다.
- **끝난 기준**: `balpyo check --check-layout --strict`가 두 덱에서 무경고, `make qa`에서 웹 |
  OnlyOffice가 참조 덱과 같은 구성으로 읽힌다 (픽셀 비교가 아니라 눈으로 — ADR 0064), PPTX를
  PowerPoint에서 열어 연결선을 끌면 따라오고 애니메이션 창에 효과가 나열된다.
