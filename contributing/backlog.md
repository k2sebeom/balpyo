# 백로그

아직 하지 않은 일의 목록이다. **순서는 정하지 않았다** — 집어 들 때 정한다. 구현된 동작은
[레퍼런스](../docs/reference/index.md)에, 계약을 바꾸는 결정은 [ADR](decisions/index.md)에 있다.
여기 있는 것은 어느 쪽에도 아직 없다.

항목을 끝내면 이 목록에서 지운다 — 끝난 일의 기록은 커밋 로그와 ADR이 맡는다.

## PPTX — OnlyOffice 검수 (P0–P3)

예제 덱 셋과 픽스처 전부(111장)를 OnlyOffice로 PPTX → PNG로 되돌려 웹과 나란히 본 결과다.
OnlyOffice는 OOXML 명세의 프리셋 공식과 글꼴 메트릭을 따라 그리는 독립 엔진이라, 우리가 쓴
리더(`parity.go`)가 보지 못하는 갈라짐 — **같은 XML을 다른 엔진이 어떻게 읽는가** — 이 드러난다.

| # | 막힌 것 | 무게 |
|---|---|---|
| P0 | `balpyo preview`의 PPTX 열이 LibreOffice만 쓴다. OnlyOffice(`x2t`)를 우선 렌더러로 두고 LibreOffice는 물러선다 | 중간 |
| P1 | **내용 폭 박스가 접힌다.** 한 줄을 꽉 채운 텍스트 박스(제목 슬라이드의 제목 · 키커 · 캡션, 카드의 라벨)는 잰 폭에 여유가 0이라, 커닝을 끈 엔진(우리 PPTX는 `kern`을 쓰지 않는다)에서 한두 px 넓어져 둘째 줄로 접히고 아래 요소와 겹친다. 예제 셋의 표지 · quarterly-review 5·6장 · 06_stack 5장 | 큼 |
| P2 | `tint(색, p%)`가 두 타깃에서 다른 색이다 — PPTX는 HSL 광도(`lumMod`+`lumOff`, PowerPoint의 "밝게 p%"), 웹은 RGB로 흰색과 섞는다(`color-mix`). 채도 높은 어두운 색에서 크게 갈린다 (12_palette 2장의 accent3) | 중간 |
| P3 | chevron의 텍스트 영역이 도형 밖으로 나간다 — 조정값이 정확히 노치 = 폭/2라 명세 공식(`?: dx x1 l`, dx = 0이면 `l`)으로는 박스 전체인데, 우리는 폭 0 열로 보고 음수 인셋으로 되돌린다. 명세대로 읽는 엔진에서 글자가 박스 왼쪽 밖으로 밀린다 (04_shape 10장) | 작음 |

OnlyOffice 쪽 한계로 보이는 것(우리 XML이 명세대로다): 그라디언트 선(`a:ln/a:gradFill`)을 첫 스톱
단색으로, 부드러운 그림자(`outerShdw blurRad`)를 아래 띠로 그린다. 고칠 대상이 아니라 검수
문서에 적을 일이다.

## 사용성 — 3회차 도그푸딩 (E3–E8)

식별자(E2…)는 커밋 로그가 그대로 쓰므로 유지한다.

| # | 막힌 것 | 무게 |
|---|---|---|
| E3 | 알 수 없는 태그 진단이 전역 어휘를 전부 나열한다 — 슬롯 · 속성 진단처럼 부모의 자식 목록으로 좁힌다 (`<ul>` 안이면 `<li>` 하나) | 중간 |
| E4 | 오타에 후보가 없다. 실제 오타 넷이 전부 편집 거리 1–2였다: `img`→`image` · `two-colum`→`two-column` · `heding`→`heading` · `elipse`→`ellipse`. 목록이 닫혀 있으므로 후보를 계산할 수 있다 | 중간 |
| E6 | 사고 하나가 경고 여럿이 된다 — 스테이지를 넘친 목록 하나가 `<ul>`과 넘친 `<li>` 각각으로 7건을 낸다. 콘텐츠 박스 이탈처럼 하나로 보고한다 (ADR 0039의 "읽히지 않는 경고는 없는 것과 같다") | 중간 |
| E7 | `layout="quote"`가 인용문을 본문 크기로 낸다 — 세 테마 모두 `blockquote`에 인용 타이포그래피가 없다 (`variant="lead"`로 우회 가능) | 중간 |
| E8 | 레이아웃 기본값 셋: `code`의 캡션이 푸터 띠에 붙어 두 줄 푸터로 읽힌다 · `title`의 제목 덩이와 저자/날짜 줄 사이가 크게 빈다 · `stat`의 `label`(18px)이 `body`(24px)보다 작아 위계가 뒤집힌다 | 중간 |

## 테마 — AWS 템플릿 필드 테스트

공식 템플릿 하나를 테마로 옮겨 보다 포맷이 담지 못한 자리들이다.

- **테마에 배경 채널이 없다.** 레이아웃 CSS는 배치 전용(ADR 0014)이라 테마가 배경을 소유할
  방법이 없다. 우회(`layout="canvas"` + 덱의 그림)는 슬롯과 PPTX 플레이스홀더를 잃고, 저자가
  좌표를 쓰고, 크롬이 되살아난다. 배경 그림 같은 **테마 소유 자산**도 함께 필요하다.
- **크롬에 로고가 들어가지 않는다.** 크롬은 `balpyo.json`의 문자열뿐이라 로고 + 저작권 덩어리를
  넣을 자리가 없다.
- **그라디언트 토큰이 없다.** 테마 variant의 `fill`/`border`는 색 토큰 이름만 받아
  `gradient(…)`가 에러가 된다 — 그라디언트가 곧 뜻인 자리에서 테마의 정체가 원고로 새어 나온다.
